# 시뮬레이션 결과 독립 검증기

시뮬레이션 결과 파일을 읽어 **승객 수, 차량 정원, 시간 제한, 성과 지표가 올바르게
계산됐는지** 확인합니다.

시뮬레이터를 다시 호출하지 않고 **별도로 계산해 비교합니다.** 같은 코드로 확인하면 같은
버그를 그대로 통과시키기 때문입니다.

<sub>모듈 M07(평가·독립 검증). 검증 대상은 M05 시뮬레이터 산출물.
검사 정의는 명세 [`docs/verifier_spec.md`](https://github.com/OpenSwProject26-2/2team/blob/ca643f63028908e6a18827abb89c4360bfb1a345/docs/verifier_spec.md)를 따릅니다 —
아직 `main`에 없고 `feat/5-simulation-core` 브랜치(PR #6)에 있어 해당 커밋을 가리킵니다.</sub>

## 1. 무엇을 검증하나요?

| 확인할 질문 | 검사 |
| --- | --- |
| 같은 수요·시드에서 같은 승객이 만들어졌나? | 발생 재현 |
| 승객이 빠지거나 중복 집계되지 않았나? | 승객 생애 · 결과 합계 |
| 버스 정원을 초과하지 않았나? | 정원 검사 |
| 기록된 시각이 차량 시간표와 맞나? | 사건 순서 · 일정 일치 |
| 정해진 승차 순서와 시간 제한을 지켰나? | FIFO · 기한 검사 |
| 충족률과 대기시간 계산이 맞나? | 지표 재계산 |
| 배차와 운행 조건을 지켰나? | 운행 제약 검사 |
| 입력·결과 파일이 중간에 바뀌지 않았나? | 체크섬 |

검사 번호와 구현 파일의 대응은 [5. 검사 항목](#5-검사-항목)에 있습니다.

## 2. 현재 검증 범위와 한계

> [!IMPORTANT]
> **`pass=true`는 "실패한 검사가 없다"는 뜻이지, "전부 검증했다"는 뜻이 아닙니다.**
>
> - **가용 차량 수(R10)와 방향별 구간(R13)은 자료가 없어 아직 검증하지 못합니다.**
>   그래서 `V16`은 항상 `not_verified`이고 `fully_verified`는 항상 `false`입니다.
> - 기본 설정에서 **승객 10,000명을 넘으면** 재계산이 필요한 검사(FIFO·기한·지표)를
>   건너뛰고 `not_run`으로 남깁니다. `--max-recompute`로 상한을 올릴 수 있습니다.
> - **검증을 통과해도 실제 운행 가능성이나 현장 성능을 보증하지 않습니다.**
>   시뮬레이션 계산이 맞는지만 봅니다.

## 3. 빠른 실행

저장소 루트에서 실행합니다. `<실행 결과 폴더>`는 실제 경로로 바꿉니다.

```sh
pip install -e .
python -m busstrike.evaluation.verify <실행 결과 폴더>
```

보고서는 기본으로 **`<실행 결과 폴더>/verifier_report.json`** 에 저장됩니다.

| 종료 코드 | 뜻 |
| --- | --- |
| `0` | **검사 실패 없음.** 전체 검증 완료라는 뜻이 아닙니다 — `fully_verified`를 따로 봅니다 |
| `1` | 검사 실패 |
| `2` | 입력 오류 (폴더·파일이 없거나 형식이 다름) |

## 4. 결과 읽는 방법

보고서에서 먼저 볼 세 줄입니다. *(설명용 예시)*

```text
pass: true
fully_verified: false
not_verified_checks: ["V16"]
```

> 실패한 검사는 없지만, V16은 아직 검증하지 못했습니다.
> 따라서 **전체 검증 완료로 표시하면 안 됩니다.**

| 값 | 뜻 |
| --- | --- |
| `pass=true` | 실패한 검사가 없음. **미실행·미검증 항목은 있을 수 있음** |
| `pass=false` | 하나 이상 실패. **검사 하나만 실패해도 전체가 `false`** |
| `fully_verified=true` | 실패·미실행·미검증이 모두 없음 |
| `not_run` | 그 검사를 실행하지 않음 (규모 상한 초과 등) |
| `not_verified` | 자료가 없어 검증하지 못함. **통과가 아님** |

### 터미널 출력

*(아래는 합성 대규모 실행을 실제로 검증한 결과에서 옮긴 것입니다. 가운데는 생략했습니다.)*

```text
검사   상태                   검사 대상      위반  단위
------------------------------------------------------------
V1   pass                 1,000       0  승객
V2   pass                89,703       0  사건
V3   pass               168,960       0  정류장 방문
...
V16  not_verified           960       0  차량
V17  pass                     6       0  파일
------------------------------------------------------------
pass=True  fully_verified=False  (통과 16 / 실패 0 / 미실행 0 / 미검증 1)
실패는 없으나 미실행·미검증 검사가 있다. "검증됨"으로 쓰지 말 것.
```

### 실패했을 때

어디가 어떻게 틀렸는지 보고서에 남습니다.
*(아래는 지표를 일부러 1 올린 사본을 실제로 검증한 결과입니다.)*

```json
{
  "pass": false,
  "failed_checks": ["V8", "V9", "V17"],
  "checks": [
    {
      "check_id": "V9", "title": "M1 충족률", "status": "fail",
      "examined": 9, "violation_count": 1,
      "violation_examples": [
        {"message": "M1.served이 재계산과 다르다",
         "where": {"path": "M1.served", "recomputed": 2, "metrics": 3}}
      ]
    }
  ]
}
```

위반 예시는 검사마다 **앞 20건**까지 싣고, 전체 건수는 `violation_count`에 있습니다.
보고서에는 입력 파일 sha256, 검증기 커밋, 엔진 커밋도 함께 남습니다.

## 5. 검사 항목

| 검사 | 확인하는 것 | 구현 |
| --- | --- | --- |
| V1 | 발생 재현 — 집계 수요와 시드로 승객을 다시 만들어 대조 | `arrivals_ref.py` |
| V2 | 사건 순서 — 시각·단계·식별자 순서, 관측 종료 이후 사건 없음 | `invariants.py` |
| V3 | 일정 일치 — 시간표에 있는 방문만, 기록된 시각이 시간표와 같음 | `invariants.py` |
| V4 | 승객 생애 — 발생 1회, 승차 ≤ 1회, 출발지에서만 승차, 하차는 목적지에서 | `invariants.py` |
| V5 | 정원 — 사건으로 센 인원 = 기록된 인원, 0 ≤ 인원 ≤ 정원 | `invariants.py` |
| V6 | FIFO·비유휴 — 승차 집합과 순서가 재계산과 같고, 빈 좌석이 남지 않음 | `invariants.py` |
| V7 | 기한 — 대기·여정 기한 만료가 재계산과 같음 | `invariants.py` |
| V8 | 결과와 합계 — 수송·미수송·미확정 분류가 배타적이고 합이 전체 인원 | `invariants.py` |
| V9 | 충족률(M1) — 분자·분모와 불확실성 범위 | `metrics_ref.py` |
| V10 | 미충족 사유(M2) — 연결 없음·운행 종료·기한 초과를 일정에서 다시 판정 | `metrics_ref.py` |
| V11 | 만차 거절(M2) — 거절 연인원과 거절 경험 승객 수 | `metrics_ref.py` |
| V12 | 대기시간(M3) — 평균·P90·임계 초과 | `metrics_ref.py` |
| V13 | 지역별 충족률(M5) — 출발 지역별 분모와 최저 지역 | `metrics_ref.py` |
| V14 | 차량별(M6) — 운행 수·수송·운행시간·거리·공차시간 | `metrics_ref.py` |
| V15 | 배차 간격(R12) — 같은 노선 연속 출발 간격 | `guards.py` |
| V16 | 운행 제약 기타 — 정원 기준·운영창·차량 duty. **R10·R13은 미검증** | `guards.py` |
| V17 | 체크섬 — 입력·산출물 파일이 기록된 해시와 일치 | `guards.py` |

## 6. 실행 옵션

| 옵션 | 기본 | 뜻 |
| --- | --- | --- |
| `--scenario DIR` | 자동 탐색 | 시나리오 폴더. 생략하면 실행 폴더 옆·상위에서 찾습니다 |
| `--out PATH` | `<run>/verifier_report.json` | 보고서 경로. `-`이면 표준출력 |
| `--max-recompute N` | `10000` | 재계산 승객 상한. 넘으면 V6·V7·V9–V14를 `not_run`으로 남깁니다 |
| `--scan full\|index` | `full` | 승차 자격 탐색 방식. `full`이 명세 문장 그대로입니다 |
| `--quiet` | — | 요약 표를 찍지 않습니다 |

`--write-realization` 없이 실행한 결과도 검증합니다. 발생 입력 파일이 없으면 집계 수요와
시드로 승객을 다시 만들어 결과 CSV와 대조합니다. 다만 체크섬 대조는 하지 못합니다.
