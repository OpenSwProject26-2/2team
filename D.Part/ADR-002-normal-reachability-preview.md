# ADR-002 — A 전달용 정상 교통 도달 가능 미리보기

- 상태: **제안 · A/D 및 팀 검토 대기**
- 날짜: 2026-11-10
- 관련 작업: [Issue #20](https://github.com/OpenSwProject26-2/2team/issues/20), D-1·D-2·D-3, M00·M06·M08
- 적용 범위: `D.Part` 안의 합성 개발용 함수와 `/__demo__/` 응답만. 공용 DTO·정식 HTTP API 계약이 아님.

## 문제

D Draft PR #19는 정상·셔틀 합성 시간표를 함께 읽고 시나리오 경로를 검색한다. 그러나 A가 잔여 수요를 판정하기 전에 필요한 **셔틀 없는 정상 교통 조회**는 별도 입력·출력이 없다. 현재 합성 fixture에는 교통카드 ID↔GTFS 정류장 매핑, 지하철, 보행망 및 실제 정상 시간표도 없다.

## 이 미리보기에서 시험할 방식

1. 정상 GTFS만 별도로 로드한다. 셔틀 feed가 누락되어도 정상 조회는 작동한다.
2. 입력은 `query_id`, GTFS `origin_stop_id`, `destination_stop_id`, offset 포함 `departure_at`이다. 교통카드 원천 ID나 좌표를 정류장 ID로 추정 변환하지 않는다.
3. 정상 운행편만으로 직행·같은 정류장 최대 1회 환승을 계산한다. 합성 파업 제외 노선 목록과 셔틀 운행편은 적용하지 않는다.
4. 결과는 `reachable`(실제 정상 운행편 연결 있음), `unreachable`(완전한 지원 범위 안에서 `NO_PATH`), `indeterminate`(데이터 부족 또는 지원 범위 밖)로 나눈다. `unreachable`만으로 전체 여정 잔여 수요를 확정하지 않는다.
5. `walking_time_s`는 보행망이 없으므로 `null`이다. 정상 시간표의 D 합성 버전을 `normal_timetable_version`으로 반환한다. 이 식별자는 M00 공용 필드명이 아니다.
6. 응답에는 `scope=synthetic_normal_bus_stop_to_stop`, `data_kind=synthetic`을 명시한다. 내부 개발용 HTTP 경로·상태 코드는 M08 정책으로 채택하지 않는다. 검색 함수는 기존 D 미리보기의 공통 탐색 로직을 내부적으로 재사용하되, A 응답에는 셔틀 운행안 ID를 노출하거나 연결하지 않는다.

## 팀 결정이 필요한 부분

| 항목 | 확인할 담당 | 실제 연결 전에 필요한 증거 |
| --- | --- | --- |
| 교통카드·정류장·GTFS ID 매핑 | A·D | 원천 namespace, 매핑 표 버전·미매칭 수, 역 플랫폼·출입구 연결 |
| 실제 정상 운행일·시간표 버전 | A | GTFS 또는 동등한 산출물, 출처·품질·누락 보고 |
| 보행·환승·최대 대기 정책 | A·D 및 전원 | 거리/시간 계산 가능한 보행망, 역 내부 연결, 정책 ADR |
| A 잔여 수요 판정 단위 | A·B·D | `single_bus_leg`와 `full_journey` 중 적용 범위, 판정 불가 처리 |
| 외부 API·응답 필드·HTTP 상태 | 전원/M08 | 공용 계약 및 API ADR, 소비자 contract test |

이 제안의 함수·JSON은 합성 입력에서 데이터 의미를 검토하기 위한 것이다. 팀 합의 후 공용 계약·정식 API·실제 데이터 어댑터를 별도 PR로 구현한다.
