# 구로디지털단지역 개발용 실제 입력 추출

기존 후보 보고서의 추천 노선·원천 노선명 그룹·공통 구간 순번을 근거로 작은 개발용 초안을 만든다. 공용 계약·공식 지역·파업 노선을 확정하거나 실행 가능한 운행안을 만드는 작업이 아니다. 기존 분석·후보 결과와 원본 자료는 수정하지 않는다.

저장소 루트에서 표준 라이브러리만으로 실행한다.

A.Part 기준 실행과 상대 경로는 [A 실행 설명](../../README.md)을 참고한다. 현재 작업 디렉터리가 A.Part이면 입력·출력에 `../raw/`, `../data/processed/`를 명시해 기존 루트 자료를 가리킨다.

```powershell
python -B -m unittest discover -s A.Part/tests -t A.Part -v
python -B A.Part/run.py extract_guro_draft --input-dir raw/from_teammate --survey-dir data/processed/taims_candidate_survey_final --output-dir data/processed/guro_real_input_draft
```

출력은 새 디렉터리여야 하며 기존 출력·입력 디렉터리에는 덮어쓰지 않는다. `data/processed/`는 Git 제외 경로다. 임의 경로에 출력해도 공개 승인을 의미하지 않는다. 실제 추출 결과는 추적 코드·문서에 복사하지 않는다.

## 출처와 보존

`survey.json`, `report.md`의 추천 근거와 `route_stops.csv`, `bus_od_0709.csv`를 읽는다. 입력 경로·파일 크기·SHA-256을 로컬 검증 보고서에 남긴다. 원본 ZIP·전체 시간대 CSV는 읽지 않는다.

후보 노선 ID의 모든 원천 방문 행을 보존한다. 원천 노선명·순번·동일 정류장 재방문·회사/일련번호와 중복 개수, 원천 CSV 줄 번호를 남긴다. 후보의 공통 순서 증거에 등장하는 노선명 그룹은 `selected_source_group`, 나머지는 `other_source_group_preserved`다. 다른 그룹을 버리지 않으며 중복을 공동운행으로 단정하지 않는다.

정류장 자료는 ID당 하나의 객체다. 이름·유효 범위 내 좌표·행정구역 후보와 원천 필드 조합을 별도 보존한다. 대표 이름·좌표는 후보가 하나일 때만 제공하며 모호성·좌표 오류를 기록한다. 표시 정보의 중복으로 OD 행이나 인원을 증식시키지 않는다. 실제 위치·CRS·행정경계를 독립 검증한 것은 아니다.

## 수요 분류

역방향 0명이라는 결과는 선택한 공통 정류장 ID 집합 내부의 분류 결과다. 반대 방향 정류장 ID로 구성한 구간은 **미추출**이며 반대 방향 수요가 없다는 뜻이 아니다. 실제 기본 추출의 정방향 내부 1,144명은 후보 전체 오전 19,854명의 **개발용 부분집합**이지 전체 영향 수요가 아니다. 숫자가 아니라 파일의 분류·인원 대사를 기준으로 재현한다.

관측 기준일과 다음 날짜 기록의 서비스일 귀속은 별개다. 시 단위 정리본을 사용하는 이번 작업에서는 다음 날짜 귀속이 미확인이다. 현재 산출물은 **B·C에 바로 넣는 최종 실행 입력이 아니다.**

노선·시간대·승하차 ID를 유지한 오전 OD 전체를 별도로 저장한다. 인원은 PSNG_NUM 합계이며 행 수·고유 승객 수·여정 수가 아니다. `07`·`08`시는 승차 태그 시간대다. 정류장 도착 시각이 아니므로 `arrival_s`를 생성하지 않는다.

공통 정류장 ID 집합으로 `both_inside`, `boarding_only_inside`, `alighting_only_inside`, `both_outside`를 배타적으로 나눈다. 다른 ID를 같은 장소로 합치지 않는다.

양끝 안 수요는 공통 목록의 위치로 `forward`, `reverse`, `same_stop`, `undetermined`를 구분한다. 동일 ID는 `same_stop`으로 보존한다. 서로 다른 끝점의 위치가 여러 개거나 노선의 원천 순번 증거·정류장 참조를 확인하지 못하면 `undetermined`다. 이는 공통 원천 순서의 선별이며 실제 운행 방향이나 방문 occurrence 배정 확정이 아니다. OD에는 원천 노선명 그룹 정보가 없어 행별 실제 그룹 배정을 주장하지 않는다.

`internal_forward_od.csv`는 이 기준의 정방향 내부 OD만 분리한 작은 입력 재료다. 나머지 수요도 전체 OD 파일과 분류 보고서에 남긴다. 포함·분리 인원, 모든 배타적 분류 합계, 내부 하위 분류 합계를 대사한다.

저장 후 `validate_saved_od`가 두 CSV를 다시 읽는다. 실제 행 수·PSNG_NUM 합계, 전체 파일에서 다시 계산한 끝점/원천순서 분류와 포함·분리 합계를 보고서와 대조한다. 저장된 분류 열만 신뢰하지 않고 정류장 ID·원천 구간 근거·노선별 정류장 참조·시간대를 검사한다. 전체 파일의 정방향 부분집합과 정방향 파일은 모든 OD_FIELDS 값과 출현 횟수를 비교한다(행 순서는 무관). source_csv_line 중복도 별도로 검사한다. 따라서 누락·중복·같은 인원으로 바꿔 넣은 잘못된 행을 합계 일치만으로 통과시키지 않는다. 결과는 `saved_csv_validation`과 `checks.included_separated_preserved`에 기록한다. 이는 생성 파일 간 검증이며 원본 OD 독립 재생성은 아니다.

## 구간과 검증

잘못된 방문 순번과 입력 파일 누락 등은 중단한다. CLI는 오류 값·행·traceback을 노출하지 않고 종료 코드 2를 반환한다. 실패 시 열린 출력 파일·입력 스트림은 닫으며, 남은 부분 출력 디렉터리는 완성 결과로 취급하지 않는다. 기존 경로에는 다시 쓰지 않고 새 경로로 재실행한다.

공통 인접 정류장 쌍은 노선별 원천 노선명·순번 증거에 연결한다. 순번은 연속이어야 하고 같은 순번에 다른 정류장이 있으면 증거 확인에 실패한다. 동일 순번·정류장의 중복만으로 별도 간선이나 수요를 만들지 않는다. 주행시간·거리·허용 회전·회차·복귀는 미확인(null)이며 직선 거리나 0초로 채우지 않는다.

합성 테스트는 분류 경계·정역순·동일 ID·반복/중복·다른 그룹 보존·이름/좌표/행정구역 모호성·원천 참조 실패·인원 보존·입력 불변·덮어쓰기 방지를 검사한다. 실제 추출은 같은 검사를 보고서에 기록하고 불일치 시 CLI 종료 코드 1을 반환한다. 실패한 출력은 완성 입력으로 사용하지 않는다.

출력 README와 `validation_report.json`에 파일 설명·출처·규모·분류·검증·부족 입력을 기록한다. C의 재방문·동일 거점 조건에 맞추려고 실제 순서·방향·수요를 변경하지 않는다. 시뮬레이션에는 별도로 검증된 주행시간·회전/회차/복귀·차량/운영 조건·운행편·승객 발생 정책과 고정 입력이 필요하다.
