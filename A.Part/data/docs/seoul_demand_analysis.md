# TAIMS 공유 정리본 버스 기초 수요 분석

서울 대상 프로젝트의 준비 분석이지만 결과는 **공유 자료 범위의 수요**다. 서울 내부 수요만 추리지 않으며 세부 지역·중단 노선을 확정하지 않는다. 행정구역 열은 표시 자료의 범위 설명에만 사용한다.

## 출처와 책임

입력은 `raw/from_teammate/`의 `bus_od_by_hour.csv`, `bus_od_0709.csv`, `route_stops.csv`, `routes_all_versions.csv`, `routes_latest.csv`, `stats.json`, `README.md`다. 공유 README의 관측일 2026-11-02와 다운로드 2026-11-06은 출력 보고서에 출처와 함께 기록하며, 참조 CSV의 `STDR_DE` 목록도 따로 기록한다.

팀원은 버스 추출·PSNG_NUM 가중 OD 집계·좌표 변환·정리본을 제공했다. 이번 코드는 그 결과의 기술 통계·순위·표시 정보 연결·합계 대사만 추가한다. 원본 ZIP, 전처리 코드 실행, OD 재생성은 하지 않는다. **공유 정리본 기반 검증이며 원본에서 재생성한 독립 검증이 아니다.**

## 실행

아래 명령은 저장소 루트 기준이다. A.Part 기준 명령·import·상대 경로 해석은 [A 실행 설명](../../README.md)을 참고한다. 실제 입력과 출력은 루트 `raw/`, `data/processed/`에 그대로 둔다.

저장소 루트, 외부 패키지 없이 Python 표준 라이브러리로 실행한다.

```powershell
python -B -m unittest discover -s A.Part/tests -t A.Part -v
python -B A.Part/run.py demand_analysis --input-dir raw/from_teammate --output-dir data/processed/taims_demand
```

출력 경로는 새 디렉터리여야 한다. 기존 분석 결과나 입력 경로 안에는 쓰지 않으며, 재실행 시 다른 출력 경로를 지정한다. 기본 출력은 기존 `.gitignore`가 제외하는 `data/processed/` 아래다. 사용자 지정 출력도 공개 가능성이 승인된 것은 아니므로 Git에 추가하지 않는다.

SQLite DB는 기본적으로 `<output-dir>/.tmp/taims-analysis-*/morning.sqlite3`에 두고 실행 종료 시 제거한다. `--temp-dir <path>`로 DB 임시 위치를 바꿀 수 있다. SQLite의 정렬 임시 파일은 SQLite/OS 기본 임시 디렉터리를 사용할 수 있어 그 저장공간도 필요하다. 실제 임시 경로·DB 크기·실행 시간·디스크 여유는 `summary.json`에 기록한다.

## 집계 기준

- 인원은 행 수가 아닌 `PSNG_NUM` 합계다. 정수 ASCII 숫자 문자열만 허용하고 음수·소수·공백을 보정하지 않는다. SQLite 정수 범위(0~2^63-1) 밖의 인원은 거절한다.
- ID·시간대는 문자열로 보존한다. ID 공백을 임의로 제거하지 않는다. 시간대는 정확히 `00`~`23`만 허용한다.
- 오전은 승차 태그 시각 [07:00,09:00), 즉 `07`·`08`시다. 오전 파일에 다른 시간대가 있으면 오류로 중단한다.
- 시간대·오전 비중의 분모는 **전체 OD 파일 인원**이다. 하차 정보 부족 등으로 제외된 원본 버스 인원까지 포함한 비중은 아니다. stats의 `psng`는 참고값으로만 기록한다.
- 오전 노선 순위는 ROUTE_ID별, OD 순위는 **노선을 합친** 승차 ID + 하차 ID별, 정류장 순위는 승차·하차 ID별 합계다.
- 순위 비중 분모는 상위 20개 합계가 아닌 **오전 파일 전체 인원**이다. 인원 내림차순, 동률은 해당 문자열 ID(OD는 승차·하차 튜플) 오름차순이다.
- 동일 출도착 정류장을 삭제하지 않는다. 0수요이면 비중은 JSON null, CSV 문자열 `null`이다.
- 필수 열 누락·인원·시간대 오류는 파일명:CSV 줄 번호:필드명으로 알린다(헤더 1행). 행 전체와 필드값은 출력하지 않는다.

## 이름·좌표와 메모리

ID로 먼저 집계한 후 표시 정보를 붙이므로 일대다 조인으로 인원이 늘지 않는다. 노선명·노선번호는 전체 버전과 latest에서 후보를 합치고, 정류장명·위경도는 route_stops의 실제 열을 사용한다. latest는 표시 참고일 뿐 관측일 유효성 판정에 쓰지 않는다.

후보가 하나일 때만 대표값을 채운다. 여러 이름·좌표는 `ambiguous`, 없으면 `missing`과 null로 표시하고 정렬한 후보 목록을 함께 저장한다. 같은 값의 반복 행은 중복 후보로 세지 않는다. 잘못된 좌표는 사용하지 않고 행 수를 보고한다. CRS·위치 정확성을 새로 검증했다는 뜻은 아니다. 오전 전체에 등장하는 ID의 미매칭·이름/좌표 모호성은 `label_coverage`에 집계한다. 표시 정보가 없어도 ID와 인원은 제공한다.

CSV는 행 단위로 읽는다. 오전 자료는 5,000행씩 SQLite에 넣고 디스크 기반 GROUP BY를 사용한다. SQLite 페이지 캐시는 8MiB로 설정하지만 전체 프로세스 메모리의 상한은 아니다. 작은 차원 자료의 ID별 이름·좌표 후보는 메모리에 보관한다. 최고 메모리는 별도로 계측하지 않는다.

## 로컬 출력과 검증

| 파일 | 내용 |
| --- | --- |
| `hourly.csv` | 24개 시간대 인원과 전체 OD 대비 비중 |
| `morning_routes_top20.csv` | 오전 노선 순위·비중·표시 후보 |
| `morning_od_top20.csv` | 오전 노선 통합 OD 순위·비중·양끝 표시 후보 |
| `morning_boarding_top20.csv` / `morning_alighting_top20.csv` | 오전 승차·하차 정류장 순위 |
| `summary.json` / `summary.md` | 전체·오전 합계·비중, 대사·stats 차이, 상위 3개 요약, 자료 범위·표시 품질·자원·한계 |

전체 시간대 합계, 각 오전 그룹의 **전체** 합계, 두 OD 파일의 오전 합계를 대사한다. stats의 od_psng/am_psng/od_pairs/am_pairs와 비교하고 차이를 보존한다. 대사 불일치·비교값 부재는 성공으로 표시하지 않으며 CLI는 보고서를 남긴 뒤 종료 코드 1을 반환한다. 입력 오류는 중단하고 코드 2를 반환한다. 실패한 실행의 디렉터리는 완성 보고서로 취급하지 않는다.

실제 분석 CSV·보고서는 로컬 제외 경로에만 두고 코드·문서에 복사하지 않는다. 합성 테스트는 가중 인원, 시간 창, 노선 통합 OD, 정류장, 동률, 0수요, 표시 중복·부족, 오류·대사 실패를 검사한다.

## 한계와 후속

관측 기준일 2026-11-02는 공유 설명·STDR_DE의 기준이다. 앞선 원본 조사에서 다음 날짜 기록도 확인됐지만, 현재 작업은 시(hour) 단위 정리본만 사용하므로 그 기록의 서비스일 귀속을 확인하거나 날짜별로 재분리하지 않는다. 관측 기준일과 모든 기록의 달력 날짜가 같다고 가정하지 않는다.

이번 완료 범위는 공유 정리본 기반 분석과 재현 가능한 개발용 추출이다. 현재 출력은 B·C에 바로 넣는 최종 실행 입력이 아니며, 엔진 입력 변환·여정 연결은 포함하지 않는다.

이번 결과는 버스 단일 이용구간 수요다. 여정의 최종 목적지·여정 수·파업 영향 여정 비율·여정 연결 성공률은 계산하지 않는다. 환승 기록과 여정 연결은 후속 작업이다. 승차 태그 시각은 정류장 도착 시각이 아니며 시 단위 파일에서 자정 이후 서비스일을 재구성하지 않는다. 방향·버전·회차·정상 시간표·실제 운행 가능성도 확정하지 않는다.
