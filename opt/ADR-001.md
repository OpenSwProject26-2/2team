# ADR-001: C의 합성 데이터 기반 첫 구현

상태: 사용자 구현 요청에 따른 C 내부 결정. 공용 DTO 채택과 A/B 통합은 팀 리뷰 대기.
관련: #3, M04, M00, M05, M07. 저장소에 없는 PRD 번호는 부여하지 않는다.

- 루트 opt/에서 표준 라이브러리만 사용한다. Python 3.11 이상.
- 첫 버전은 single_bus_leg, 고정 후보, 동일 정원·가용시간·출발/복귀 거점을 가진 차량만 지원한다. 이질 차량이나 별도 차고지 이동이 필요한 입력은 OUT_OF_SCOPE로 거절한다.
- 수요는 이미 생성된 도착 시각과 인원이다. seed로 실행 중 다시 생성하지 않는다.
- 노선의 outbound는 승객 수송, return_segments는 복귀 공차 구간이다. 복귀 중 수송은 하지 않는다. 반대 방향 수요는 별도 outbound 후보가 필요하다.
- 배차는 차량 수와 순환시간에서 유도한다. 주행·정차·종점 회차·공차 복귀를 포함하고, 복귀 완료가 운영 종료를 넘는 운행은 생성하지 않는다.
- C는 정적인 예상 운행편 용량으로 근사 평가한다. B의 사건 기반 시뮬레이터나 독립 검증기를 구현하지 않는다.
- 충족 인원 우선, 동점은 예상 평균 대기·운행거리·배분 벡터 순서. B 재평가는 실제 P90을 사용한다.
- 기존 M00 최소 필드를 보존하는 draft ServicePlan을 내보낸다. module-owned routes에 배분을 담고 duties/trips는 비운다. schedule_status=pending_b, plan_mode=simulation을 부가한다.
- 공용 계약은 변경하지 않는다. opt/models.py는 공용 계약으로 확정되지 않은 내부 프로토타입이다.
- 개발용 상위 후보 선택 후 미사용 평가 입력은 별도 평가한다. 평가 입력으로 탐색하거나 재선택하지 않는다.
- SHA-256은 이 프로토타입의 정규 JSON 입력 체크섬이다. 팀 전역 해시 방식 채택을 주장하지 않는다.

후속: A/B가 모델·시간 의미·공차 조건을 리뷰하고 실제 포트를 연결한다. 이질 차량, 서로 다른 출발 거점, 자동 단축·통합 후보 생성은 별도 변경으로 진행한다.
