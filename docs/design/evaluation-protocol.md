# 운행안 비교 평가 프로토콜 (M07)

- 상태: **초안 · 팀 검토 필요 · 아직 어떤 운행안도 실행하지 않았다**
- 범위: 파업 대체 운행안 여러 개를 같은 조건에서 비교하고 결과를 기록하는 절차
- 연결: Issue #15, M00 계약 §5·§6, `docs/verifier_spec.md`(M05 독립 검증)
- 이 문서는 **무엇을 어떤 조건에서 재고 무엇을 재지 않는지**만 정한다. 어느 안이 좋은지
  주장하지 않는다.

## 1. 왜 이 문서가 먼저 필요한가

비교할 운행안 중 하나는 **우리가 만든 것**이다. 우리가 평가지표도 정한다. 결과를 본 뒤에
지표를 고르면 "우리가 이기는 지표를 골랐다"가 되어 결론이 무의미해진다.

그래서 **운행안을 하나라도 실행하기 전에** 지표와 규칙을 고정하고, 고정한 시점을 커밋으로
남긴다. 이 문서가 그 기록이다.

| 규칙 | 내용 |
| --- | --- |
| 사전 고정 | §5의 1차 지표·보조 지표·통계 규칙과 §4.2의 표본 규칙은 첫 실행 전에 정한다 |
| 변경 절차 | 고정 후 변경은 **새 커밋**으로 이유와 날짜를 남긴다. 조용히 바꾸지 않는다 |
| 금지 | 결과를 본 뒤 1차 지표를 바꾸는 것, 유리한 지표만 보고하는 것 |
| 증명 | 이 문서를 병합한 커밋 해시와 날짜가 고정 시점이다 |

## 2. 비교 대상

| 안 | 출처 | 결정론 | 비고 |
| --- | --- | --- | --- |
| 지자체안 | 실제 공개 자료 | 1개 고정 | 수집 출처·수집일을 §4.1에 기록 |
| 범용 AI안 (GPT) | 상용 LLM | **비결정론** | §4.2 표본 규칙 적용 |
| 범용 AI안 (Claude) | 상용 LLM | **비결정론** | 〃 |
| 범용 AI안 (Gemini) | 상용 LLM | **비결정론** | 〃 |
| 우리 알고리즘안 | `busstrike.planning` | 1개 고정 | 같은 입력에 같은 출력 |

AI안은 모델마다 여러 번 뽑으면 매번 다른 답이 나오고, 지자체안과 우리 안은 하나뿐이다.
**이 비대칭을 숫자 하나로 뭉개지 않는다**(§5.5).

## 3. 공정 비교 조건

모든 안을 **같은 입력·같은 변환·같은 정책**으로 돌린다. 하나라도 다르면 그 비교는 버린다.

| 조건 | 내용 | 어기면 생기는 일 |
| --- | --- | --- |
| C1 같은 수요 | 모든 안이 동일한 `RunInputs`(사전 생성 승객, 발생 시각)를 쓴다. seed가 같다는 이유로 입력이 같다고 보지 않고 checksum으로 확인한다 | 수요가 다르면 충족률을 비교할 수 없다 |
| C2 같은 차량 수 | **가용 차량 대수와 정원을 모든 안에 동일하게 준다** | 대수가 많은 안이 이기는 것은 당연하다. 비교가 아니다 |
| C3 같은 시간표 생성기 | 안은 `노선 + 노선별 대수`만 준다. 배차 시각은 모든 안에 같은 생성기가 만든다 | 배차를 손으로 다듬은 안이 유리해진다 |
| C4 같은 정책 | 최대 대기·최대 총 이동·정차·회차·운영창·drain을 동일하게 둔다 | 기한이 느슨한 안이 유리해진다 |
| C5 출처 숨김 | 시간표 생성기·엔진·검증기·지표 계산기는 **어느 안인지 읽지 않는다.** 출처는 별도 매니페스트에만 둔다 | 출처에 따라 다르게 동작할 여지가 남는다 |
| C6 같은 망 | 같은 `NetworkSnapshot`(정류장·구간 이동시간)을 쓴다 | 이동시간이 다르면 도착 시각을 비교할 수 없다 |

C5는 M05 설계(`docs/design/simulator.md` §1.6)의 "엔진은 운행안의 출처를 읽지 않는다"와 같은
취지다.

### 3.1 차량 수를 맞출 수 없을 때

지자체안의 실제 투입 대수가 고정이라 다른 안에 맞출 수 없는 경우가 있다. 그때는 둘 다 낸다.

1. **같은 대수 비교** — 지자체안의 실제 대수를 모든 안에 주고 비교한다(주 비교).
2. **대수 민감도** — 대수를 바꿔 가며 각 안의 충족률 곡선을 낸다. "N대일 때"를 명시한다.

"우리 안이 더 좋다"를 대수가 다른 상태로 쓰지 않는다.

## 4. 운행안 수집과 보존

어느 안이든 **원본 그대로 보존**하고, 우리 입력 형식으로 바꾼 과정을 따로 기록한다.
변환에서 해석이 들어간 지점은 전부 적는다. 변환이 곧 평가에 영향을 주기 때문이다.

보존 위치와 파일 규칙은 `experiments/plans/README.md`, 변환 규칙은
`experiments/plans/schema.md`에 둔다.

### 4.1 지자체안

- 출처 URL, 수집일, 자료 형태(표·PDF·이미지), 이용 조건을 기록한다.
- 저장소에는 **노선·대수 등 비교에 쓰는 집계만** 넣는다. 원문 전체를 복제하지 않는다.
- 노선이 우리 망의 정류장 ID와 맞지 않으면 매칭 규칙과 **매칭 실패 건수**를 적는다.
  실패를 임의로 메우지 않는다.
- 자료에 없는 값(대수, 운행 시간대 등)은 추정하지 말고 "미상"으로 두고, 비교에서 그 안을
  어떻게 다룰지 정한다.

### 4.2 범용 AI안

같은 프롬프트라도 모델은 매번 다른 답을 낸다. 아래를 고정한다.

| 항목 | 규칙 |
| --- | --- |
| 프롬프트 | 모델 3개에 **같은 프롬프트**를 쓴다. 전문을 저장소에 보존한다 |
| 입력 정보 | 세 모델에 주는 정보(망·수요 요약·차량 수·정책)를 동일하게 맞춘다 |
| 모델 기록 | 모델명·버전·호출 날짜·설정(temperature 등)을 기록한다 |
| 표본 수 | 모델당 **n회**(권장 3회) 뽑는다. n은 첫 호출 전에 정한다 |
| 선택 규칙 | **n개를 전부 실행하고 전부 보고한다.** 중앙값과 최소·최대를 같이 적는다 |
| 금지 | n개 중 **제일 좋은 것만 보고**하는 것. 실패한 출력을 조용히 버리는 것 |
| 실패 처리 | 형식이 깨져 변환할 수 없는 출력도 **건수와 사유를 기록**한다. 재시도 횟수도 적는다 |

"제일 좋은 것만 보고"가 금지인 이유: 우리 알고리즘안은 결정론이라 1개뿐이다. AI안만 n개 중
최선을 고르면 AI에 유리한 비교가 된다. 반대로 최악을 고르면 불리하다. 전부 보고가 유일하게
편향 없는 방법이다.

### 4.3 우리 알고리즘안

- `busstrike.planning`의 커밋 해시와 입력 설정을 기록한다.
- 같은 입력에 같은 출력이 나오는지 확인한다(2회 실행 비교).

## 5. 지표

### 5.1 현재 정의가 갈려 있다 — 먼저 합의가 필요하다

| 출처 | 상태 | 충족률 정의 |
| --- | --- | --- |
| `sim/metrics.py` M1–M6 | PR #6 Draft | `served / total`. censored는 하한·상한으로 분리 |
| `docs/design/simulator.md` | PR #28 Draft | 수송률 `transported/generated`과 충족률 `satisfied/generated`을 분리. 충족 = 수송 중 총 이동 ≤ 상한 |
| M00 계약 | 검토 대기 | 지표 정의 **없음** |

같은 실행을 넣어도 숫자가 다르다. 기한을 넘겨 도착한 승객을 앞쪽은 미충족으로 빼고, 뒤쪽은
수송에는 넣고 충족에서만 뺀다. **비교를 시작하기 전에 하나로 정해야 한다.**

아래 §5.2–§5.5는 M07이 제안하는 정의다. 팀 합의 전에는 확정이 아니다.

### 5.2 1차 지표 — 충족률

```
충족률 = (기한 안에 목적지에 도착한 승객 수) / (발생한 전체 승객 수)
```

- **분모는 발생 승객 전체**다. 노선이 닿지 않아 애초에 탈 수 없던 사람도 분모에 넣는다.
  분모에서 빼면 **적게 커버하는 안이 유리해진다**. 이게 이 지표에서 가장 중요한 선택이다.
- 분자는 `발생 → 목적지 도착`이 정책의 최대 총 이동시간 안에 끝난 승객이다.
- 1차 지표는 **하나**다. 여러 지표를 섞어 종합 점수를 만들지 않는다. 가중치를 우리가 정하면
  결론도 우리가 정하는 것이 된다.

### 5.3 보조 지표

1차 지표만으로는 "왜 그런지"와 "누가 못 갔는지"를 알 수 없다. 아래를 함께 낸다.

| 지표 | 보는 것 |
| --- | --- |
| 미충족 사유 분해 | 연결 없음 / 운행 종료 / 대기 초과 / 여정 초과 / 만차. 합 = 미충족 인원 |
| 대기시간 분포 | 평균·P50·P90. 탑승자 기준과 충족자 기준을 **따로** 낸다 |
| 총 이동시간 분포 | 평균·P50·P90 |
| **지역별 최저 충족률** | 전체 평균이 높아도 특정 지역이 방치될 수 있다. 형평성 |
| 만차 거절 | 거절 연인원과 거절 경험 승객 수 |
| 차량 생산성 | 차량 1대당 충족 인원, 공차 시간 비율 |
| 필요 차량 수 | 같은 충족률을 몇 대로 달성했는지 (§3.1의 대수 민감도) |

보조 지표는 **1차 지표를 대체하지 않는다.** 1차에서 지면 보조에서 이겼다고 결론을 뒤집지
않는다. 보조는 설명에 쓴다.

### 5.4 통계 규칙

| 항목 | 규칙 |
| --- | --- |
| 백분위 | nearest-rank. 오름차순 N개 중 `ceil(p·N/100)`번째 |
| 표본 0 | `null`. **0으로 채우지 않는다** |
| 반올림 | 보고 표에서만 한다. 계산 중에는 하지 않는다 |
| 비율 | 분모가 0이면 `null` |

### 5.5 불확실성을 숨기지 않는다

- **관측 종료 시 미확정(censored)** 승객은 하한·상한으로 낸다.
  하한 = 충족 / 전체, 상한 = (충족 + 미확정) / 전체. **하나의 점수로 뭉개지 않는다.**
- **AI안의 표본 분산**은 중앙값과 최소·최대를 함께 적는다. 평균 하나로 적지 않는다.
- 두 안의 차이가 표본 분산보다 작으면 "차이가 있다"고 쓰지 않는다.

## 6. 이 비교로 말할 수 없는 것

보고서에 그대로 옮겨 적는다.

- **실제 운행 성능이 아니다.** 합성 수요·합성 시간표 위의 시뮬레이션 결과다.
- **지자체안이 불리하게 나오는 것이 그 안이 나쁘다는 뜻이 아니다.** 지자체안은 기사 근무,
  차고지, 인가, 민원 같은 실제 제약을 반영해 만든 것이고 시뮬레이션은 그 제약을 모른다.
  AI안과 우리 안은 그 제약을 받지 않은 상태로 만들어졌다.
- **운행 승인·배차 근거가 아니다.** `selected`는 실험상의 선택이다.
- 평가 단위가 단일 구간(`single_bus_leg`)이면 **환승이 필요한 이동은 평가되지 않는다.**
  다른 평가 단위의 결과를 같은 그래프에 섞지 않는다 — M00 §3.1이
  *"두 scope의 결과를 같은 충족률 그래프에 섞지 않는다"* 로 정한 것과 같다.
- 집계 OD로는 개인의 실제 경로·환승을 알 수 없다. 거기서 나오는 결론은 쓰지 않는다.

## 7. 결과 기록 양식

### 7.1 실행 1건마다 남기는 것

| 항목 | 예 |
| --- | --- |
| 운행안 ID·출처 | `plan_id`, `revision`, 출처(지자체 / GPT #2 / 우리) |
| 입력 | `input_bundle_id`, 입력 checksum, 망 스냅샷 ID |
| 정책·차량 | 최대 대기·최대 총 이동·drain·가용 대수·정원 |
| 코드 | 엔진 커밋, 운행안 생성 코드 커밋, 지표 정의 버전 |
| 검증 | **독립 검증기 통과 여부**와 `verifier_report.json` 위치 |
| 결과 | 1차 지표, 보조 지표, 불확실성 범위 |

### 7.2 비교 표

```text
                    충족률(하한–상한)   미충족 최다 사유   P90 대기   지역 최저   차량수
지자체안                0.62–0.62        연결 없음         18분       0.31        50
GPT      (n=3, 중앙값)  0.58 (0.51–0.63) 만차              22분       0.19        50
Claude   (n=3, 중앙값)  0.61 (0.57–0.64) 연결 없음         20분       0.24        50
Gemini   (n=3, 중앙값)  0.55 (0.48–0.60) 운행 종료         25분       0.12        50
우리 알고리즘           0.00–0.00        -                 -          -           50
```

위 숫자는 **양식 예시이며 측정값이 아니다.** 실제 표에는 측정값만 넣는다.

### 7.3 표기 규칙

- **독립 검증기를 통과하지 않은 수치는 "독립 검증 전 잠정"으로 표기한다.** 검증 전 수치로
  비교 결론을 쓰지 않는다(M00 §6, `docs/verifier_spec.md` §1).
- 합성 결과와 실제 자료 기반 결과를 **같은 표에 섞지 않는다.** 섞어야 하면 열을 나누고
  어느 쪽인지 적는다.
- 실행하지 못한 안·실패한 출력은 빈칸이 아니라 **"미실행" / "변환 실패"** 로 적는다.

## 8. 미정 · 후속

| 항목 | 필요한 결정 |
| --- | --- |
| 지표 정의 통합 | §5.1의 세 정의 중 하나로. 팀 합의 필요 (별도 Issue) |
| 평가 단위 | `single_bus_leg` / `full_journey` (M00 D02) |
| 최대 대기·총 이동 | M00 D07. 현재 제안값 1200초 / 3600초는 미승인 |
| 가용 차량·초기 위치 | M00 D03 |
| 지자체안 자료 | 출처 URL과 형식 확인 후 §4.1·`schema.md` 구체화 |
| AI 표본 수 n | 권장 3. 비용과 분산을 보고 확정 |
| 비교 계산기 구현 | 지표 정의가 고정된 뒤 `src/busstrike/evaluation/` 에 추가 |

이 문서가 병합된 시점이 지표 고정 시점이다. 이후 변경은 커밋 이력에 남는다.
