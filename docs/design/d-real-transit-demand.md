## ID와 계산 의미

### 지도 체크의 운행 가정

`시내버스·마을버스·경기버스` 지도 체크를 끄면 해당 수단만 `disabled_modes`로 `/api/d/transit/real-demand`에 전달된다. 버스는 A GTFS의 노선 유형과 `stop_route_hourly`의 `ROUTE_ID`를 맞춰 운행 중단 수단의 정류장별 승차를 합산한다. 지하철 지도 체크는 역 표시 전용이며 화면 버스 수요원 계산에 전달하지 않는다. 특정 파업 노선과 전체 시내버스 OFF가 겹쳐도 동일 행은 한 번만 집계한다. 체크를 켜면 해당 노출이 빠지고 정상일 버스 관측 승하차 합계는 유지된다. `셔틀`은 합성 DEMO에서 계산 입력으로 연결된다. 버스 정류장·수요원 표시 체크는 계산 입력이 아니다.

화면에서는 운행 OFF 시 해당 노선 선을 숨기고, 정상일 관측 승차에서 제외·파업 노선 승차 노출을 빼서 **운행 노선 관측 승차 원**을 같은 위치에 다시 그린다. 노출 건수는 별도 숫자로 제공한다. 저장된 C/B 시뮬레이션 화면에서는 같은 조건의 공간 결과가 없으면 기본 저장 결과를 유지하고 조건 효과가 미반영되었다고 알린다. 두 출처의 원을 같은 수요처럼 전환하지 않는다. 노출 원은 재배치된 승객이나 최종 미충족 인원을 뜻하지 않는다.

시내버스·마을버스·경기버스의 정상일 승차를 같은 k5 날짜·시간 기준으로 서울 전체 약 3.2km, 선택 구 약 1.25km 고정 격자에 모아 **한 위치당 하나의 버스 원**으로 그린다. 원 크기는 420ms 동안 보간한다. 원의 수치는 정상일 버스 승차 BOARD에서 제외·파업 노선의 affected_board를 뺀 값이다. 운행 조건 변경 시 계산 항목이나 색을 바꾸지 않는다. 지하철 관측값은 API 통계로 유지하지만 화면 버스 원에는 합산하지 않는다. 지도 원의 합계는 **승차 건수**이며 고유 인원이 아니다. 경기버스는 현재 A GTFS에 대응하는 k5 승차 행이 없어 해당 영향 원에 0건으로 남는다. C/B의 `affected_maeul`, `affected_gg` 잔여 수요는 입력 범위·모집단·계산 단계가 달라 k5에 더하지 않는다.

구로구 2026-10-26 07시 실제 k5/A GTFS 기준 운행 중단 **승차 노출량**은 전체 ON 0명, 시내버스 OFF 11,644명, 지하철 OFF 23,236명, 둘 다 OFF 각각 11,644명·23,236명, 복구 시 0명이다. 이 값은 실제 미충족이 아니다. 정상 버스·다른 수단의 우회 가능성과 잔여 정원에 대한 동일 모집단 결과가 없어 최종 미충족을 계산할 수 없다.

- 버스: `ROUTE_ID`와 A GTFS `route_id`를 정확히 비교한다. 700번은 `100100440`, 701번은 `100100103`으로 확인했다. 노선번호만으로 파업을 판정하지 않는다. UI의 파업 지정은 **사용자 가정**이며 실제 파업 공고가 아니다. `BSST_ID`는 `reference/stops.csv`로 좌표를 얻는다. A GTFS와 기준표 노선 ID 교집합은 632개다.
- 지하철: `RIDE_STN_ID`, `ALGH_STN_ID`를 숫자 문자열이면 `zfill(4)` 해 `OUT_STN_NUM` 및 A GTFS 지하철 `stop_id` 양쪽과 일치시킨다. 기준표에 좌표가 없어서 지도 좌표는 A GTFS 역 좌표를 쓴다. `-1` 등 미매칭은 행·승객 수로 별도 보고한다.
- 정상일 관측: 시간대·지역 안의 버스 정류장별 `BOARD/ALIGHT`, 지하철 출발역·도착역별 `PSNG`를 각각 합산한다. `hour=all`은 기존 운영자 오전 창인 06~09시 합이다. 원 크기는 선택한 승차 또는 하차 인원이다. 시내·마을·미분류 버스는 A GTFS 노선 유형으로 분류하며, A 피드에 없는 경기버스 자체 승하차는 있다고 표시하지 않는다.
- 파업 영향: 선택한 버스 `route_id`의 **정상일 승차 노출량**만 별도 합산한다. 동일 행을 정상일 관측에서도 유지한다. 파업 없음·확대·복구에서 관측 총합은 변하지 않는다. 버스·지하철 원 표시 체크는 계산 입력이 아니다. 실제 미충족 원은 그리지 않는다.

이 API의 `unmet_status=unavailable_no_capacity_or_passenger_rerouting`은 전환·흡수·셔틀 후 미충족을 산정하지 못했다는 뜻이다. `strike.py`와 `absorb.py`의 C 지역 모델은 **걸어서 역에 갈 수 없고 지정 역 정류장이 있는 흐름**을 대상으로 하므로 서울 전체 버스·지하철 OD와 모집단이 다르다. 그 결과를 이 화면의 전체 승차 노출량에서 다시 빼면 중복 차감과 범위 오류가 생긴다. C 지역별 동일 날짜·시간의 파업 등록부, `demand_flows`, 정차 순서, 수단별 잔여 정원과 역 접근 및 열차 잔여 정원, B/M05 `passenger_outcomes.csv`, M07 검증 보고서가 같은 버전으로 제공되면 `d_transit_data.py`의 `real_demand()` 다음 단계에 범위·ID 교차표를 확인해 연결한다. 현재 `bundles_v4`의 `demand_bins.csv`는 **셔틀 투입 전 C/B 입력**이고 M05 승객 결과가 아니다.

### 지도 표시 보정

버스 관측 원은 같은 날짜·구에서 정상일 승하차량으로 위치를 고정한다. 확대·축소만으로 격자를 다시 묶지 않는다. 버스 체크에 따라 운행 노선 승차량이 바뀌어도 같은 격자 ID와 중심을 유지하고 반지름만 보간한다. 빈 윤곽 원과 빨간 영향 원은 표시하지 않는다. 원은 운행 노선의 관측 승차 건수 하나만 뜻한다. 경기버스는 대응 승차 행이 없어 OFF 시 영향량 0건으로 표시한다. A GTFS 버스 도로 선형이 없으면 해당 선은 그리지 않고 정류장만 남긴다. 강동구의 부분·왕복 RoadNet 추정 선형은 별도 GeoJSON을 연결했을 때만 표시하며, 비어 있는 구간을 직선으로 채우지 않는다. 선의 표시 방식은 수요 계산을 바꾸지 않는다. 자치구를 선택하면 해당 구 경계만 표시한다.

원의 크기 근거: `share_k5/seoul/YYYYMMDD/stop_route_hourly.csv`에서 선택 날짜의 `H=07`, `H=08` 및 지도 구역에 매칭된 버스 정류장·노선 승차를 읽는다. 같은 격자 안의 시내·마을·경기버스 `BOARD`를 합친 뒤, 제외하거나 파업 지정한 노선의 중복 제거된 `affected_board`를 뺀 건수를 원의 `passenger_count`로 사용한다. 경기버스 매칭 행이 없는 현재 자료에서는 경기버스 체크만 바꾸어도 수치가 변하지 않는다. 원 중심은 해당 격자의 정상일 `BOARD+ALIGHT` 가중 평균 좌표이며 운행 체크에 따라 이동하지 않는다. 지도 반지름은 0건→0px, 100건→5px, 1,000건→11px, 5,000건→17px, 20,000건→24px 사이를 선형 보간한다. 확대·축소해도 격자와 이 픽셀 반지름은 유지된다. 구를 바꾸면 집계 구역과 격자가 달라져 원 위치가 바뀐다. 이 값은 정상일 승차 기록이며 실제 운행 중단 후 잔여·미충족 인원이 아니다.

## 남은 연결

1. 실제 파업 등록부: `route_id`, 노선번호, 운수사, 파업 시작·종료 시각, A 피드 버전. 현재 확인한 로컬 `reference/routes.csv`와 k5 표에는 파업 상태가 없다. C 지역 번들의 등록부는 해당 지역·버전의 후보 목록이므로 서울 전체 실파업 사실로 취급할 수 없다.
2. 우회·정원: 버스/지하철의 날짜·시간별 운행편과 구간별 잔여 정원, OD별 대체 경로·역 접근 가능성. `sources/subway/`의 시각표·혼잡도만으로 특정 승객의 추가 탑승 여력을 검증하지 못했다.
3. 셔틀 후 미충족: 같은 모집단의 B/M05 승객별 또는 정류장별 수송 결과, 차량·노선 ID, 검증된 정류장 교차표, M07 검증 상태. 자료가 도착하면 실제 모드의 `unmet` 레이어를 별도 API 출력으로 연결한다.
4. GIS 7호선: 기존 측정의 한 역 약 1.1km 오차가 재현되면 20역 이상·95% 이상·최대 2역 불일치인 물리 회랑을 `rail_gis_partial_corridor`로 표시하고 불일치 역 ID를 보고한다. 오늘 실행 환경에서는 Esri 요청이 연결 거절되어 현재 1~9호선 재검증·브라우저 선로 확인은 미완료다. 선로가 표시돼도 급행·지선·방향별 GTFS 운행 경로로 해석할 수 없다.
