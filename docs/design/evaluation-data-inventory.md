`자치구정류장코드분류.xlsx`로 구 단위 대응(구로구 = ARS `17` ↔ ID `116`)은 확인했고 지도의
ARS 112개가 전부 구로구임을 확인했다. 하지만 **뒷자리는 대응하지 않는다**(112건 전수 시험,
일치 0건). 이름으로만 맞춘 결과 114개 중 **모호 54건·실패 32건**이 남았다.

좌표로 확인해 보니 모호한 후보들은 **41/54가 100 m 이내**이고 1 km를 넘는 것은 0건이다.
즉 **위치는 거의 맞고 방향이 안 정해진다.** 엉뚱한 곳으로 갈 위험은 없지만 노선 방향이
뒤집히면 결과가 달라진다. OA-21231에 ARS와 정류장 ID가 함께 있어 확보하면 대부분 해소된다.

## 2. D1 지자체 셔틀 (구로구 2026년 1월)

| 항목 | 주민 공지 | 보도자료 (2026-01-12) |
| --- | --- | --- |
| 노선 | 7개 | 7개 |
| 오전 차량 | **13대** | **11대** |
| 오후 차량 | 13대 | 10대 |
| 정원 | 미기재 | 45인승 |
| 운행시간 | 07:00–22:00 | — |

**두 공식 자료의 차량 수가 다르다.** 작성일만으로 실제 운행 대수를 확정하지 않는다.

- **13+13=26 또는 11+10=21을 07–09시 동시 가용 대수로 쓰면 안 된다.** 오전·오후 교대 배치일 수 있다.
- 확인 전까지는 **오전 11대 조건과 13대 조건을 각각 돌리고 둘 다 보고한다**(프로토콜 §3.1).
  이것을 "실제 운행 재현"이라고 부르지 않는다.
- 확인처: 구로구 교통행정과 비상수송대책본부 02-860-2475 (주민 공지 기재). **연락하지 않았다.**
- 확인할 것: 07–09시 실제 동시 차량 수, 노선별 배분, 좌석 정원, 방향별 정차 순서,
  첫 출발·배차 간격 또는 출발표, 회차·복귀, 임시 정류장 위치, 이용 집계 유무.

공표된 7개 노선 연결:
구로동1(신도림–남구로) · 구로동2(디지털단지오거리–구로역) · 고척동1(고척사거리–오류동역) ·
항동1(항동지구–천왕역) · 구로동3(디지털단지오거리–구로디지털단지역) ·
수궁동1(궁동생태공원–온수역) · 항동2(항동지구–온수역–오류동역)

**라이선스**: 구로구 페이지에 공공누리 **4유형(출처표시·상업적이용금지·변경금지)**. 원본 노선도
이미지를 저장소에 재배포하지 않는다. 비교에 쓰는 **정류장열·대수 집계만** 넣고 출처를 함께 적는다.

### 다른 자치구

서대문구 2026-01 공지: 5개 노선, 06:00–22:00, 첨부 제목에 33대. 공공누리 3유형.
**서울 전체 비교로 확장할 때는 자치구별 같은 날짜·같은 버전의 계획을 모아야 한다.
구로구 13대를 서울 전체 자원 기준으로 쓰지 않는다.**

### 2026년 9월 자료

더 최신이지만 **첫차 전 협상 타결로 비상수송대책이 해제됐다.** 실제 운행 실적이 아니다.
쓴다면 **"파업 대비 계획을 적용한 가상 시나리오"** 로 이름 붙이고 1월 자료와 섞지 않는다.

## 3. D2 구간 운행시간

| 출처 | 내용 | 주의 |
| --- | --- | --- |
| 서울 OA-21217 | 일자·1시간 단위 노선별 정류장–정류장 **평균** 운행시간 | 최근 30일만 API 제공. 과거는 ZIP |
| T-DATA 1039 | 같은 용도 API. `stdr_de, route_id, from_sta_id, to_sta_id, from_sta_sn, to_sta_sn, trip_time_07h…` | 인증키 필요 |

확보 전 확정하지 않을 것:

1. **시간 단위** (초·분)
2. **정차 시간 포함 여부** — 포함돼 있으면 기본 정차를 다시 더하지 않는다
3. **0·결측의 의미**
4. `trip_fcnt`가 시간대별 표본 수인지 — **임의로 해석하지 않는다**
5. 07–09시 평가에 07시·08시 값을 쓸지, 09시를 포함할지

**평균 자료에서 개별 차량 운행시간의 중위값·P90을 복원할 수 없다.** 구간시간을 고정 평균으로
쓰면 시뮬레이션에 구간 변동이 없다는 뜻이고, 그 사실을 결과에 적는다.

### DX를 구간시간으로 쓰지 않는 이유

원시 DX의 승차→하차 차이는 **해당 이용구간 전체 시간**이다. 여러 정류장을 건너뛴 OD 시간을
인접 구간 시간으로 넣으면 틀린다. 카드 태그 시각은 차량 도착 시각도 아니다(M00 §2.2).

### 없는 구간 처리

값이 없는 구간은 **UNKNOWN**으로 두고, 그 구간이 영향을 주는 **수요 가중 포함률**을 함께
보고한다. 0초나 직선거리로 메우지 않는다(M00 §2.2).

### 3.1 좌표를 쓸 때 주의 — 팀 공유 필요

`VW_KSCC_DH_CARD.csv`의 정류장 좌표는 두 가지가 통념과 다르다. 확인하지 않고 쓰면 전부
엉뚱한 위치가 된다.

1. **열이 뒤바뀌어 있다.** `BSST_LAT`에 경도(126°…), `BSST_LON`에 위도(37°…)가 들어 있다.
2. **10진 도가 아니라 도·분(DMM)이다.** `12653.3534` = 126° 53.3534′ = 126.88922°.

네 해석을 전수 시험한 결과:

| 해석 | 서울 범위(37.4–37.7 N, 126.7–127.2 E) 안 |
| --- | --- |
| 열 그대로 + 10진도 | 0.0% |
| 열 그대로 + DMM | 0.0% |
| 열 교환 + 10진도 | 0.0% |
| **열 교환 + DMM** | **96.0%** |

M00 §2.2가 *"좌표는 검증 후 CRS와 축 순서를 함께 저장"* 하라고 한 바로 그 경우다.
거리·근접 계산을 하는 모듈(M02 망, M03 수요, M06 경로)이 같은 교정을 적용해야 한다.

## 4. D3 파업 대상 노선 등록부

공식 공지 기준으로 파업 대상은 **서울시 시내버스**이고, **마을버스·경기버스·지하철은 정상
운행**이다. 따라서 "마을버스만 빼고 전부"로 거르면 범위가 틀린다.

로컬 `VW_KSCC_DH_CARD.csv`에 필요한 열이 이미 있다.

```
COMBINE_TYPE  시내/마을 구분    TRCM_ID, TRCM_NM  운수사
ROUTE_ID, ROUTE_NM              STDR_DE  기준날짜
```

- DH의 구분은 `시내` 38,292행 / `마을` 7,936행이며 **정류장 방문 행 수이지 노선 수가 아니다.**
- DH의 고유 `ROUTE_ID`는 681개. **`DO`의 1,423행을 활동 중인 파업 대상 노선 수로 보면 안 된다.**
- 공식 스키마상 `DO.ROUTE_TYPE_CD`는 미사용 빈값이다. **이 열 하나에 파업 필터를 의존하지 않는다.**

만들 표:

```
route_id, operator_id, operator_name, jurisdiction, route_type,
strike_state, valid_from, valid_to, source_url, match_status
```

`strike_state`는 **affected / unaffected / unknown** 셋으로 구분한다.
서울을 지난다는 이유나 마을버스가 아니라는 이유만으로 `affected`로 분류하지 않는다.

대조할 공식 등록부: 서울 월별 버스노선 기본정보 OA-15066
(목록에 `서울시버스노선기본정보(20260108).xlsx`), 노선마스터 OA-21230 / T-DATA 1033.
