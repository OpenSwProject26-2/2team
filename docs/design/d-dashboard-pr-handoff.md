# D 운영자 대시보드 PR 인수인계

이 문서는 **저장소에 올릴 코드**와 **저장소 밖에서 별도로 연결할 데이터**를 구분한다. 실제 C/B/M07 화면은 저장된 결과를 조회하고, 합성 DEMO만 운행 조건을 바꿀 때 가상 수요를 다시 평가한다. 아래 2026-11-19 기록은 당시 검증 내역이며 현재 실행 상태는 2026-11-26 항목을 우선한다.

## 2026-11-26 PR 준비 현황

같은 날 확인한 실행 서버의 `/api/d/sources`에서는 A GTFS와 서울·경기 버스 선형이 `ready`다. 철도 GIS, B/C/M07 산출물, `transport_demand`는 `unavailable`이므로 이 서버 화면에서 해당 결과를 검증했다고 보아서는 안 된다. 아래 B/C/M07 기록은 별도 원본 산출물을 연결해 확인한 과거 실행 내역이다.

현재 로컬 강동구 지도는 A GTFS, `seoul_transit_data`, 서울 버스 선형 GeoJSON, GBIS 공식 경기버스 GeoJSON을 함께 읽는다. `/api/d/sources`에서 서울 버스 선형 **130개**(그중 왕복 패턴 RoadNet 추정 9개), GBIS 공식 선형 **23개**가 연결됐다. 강동구 노선 49개는 각각 표시 가능한 선 구간이 있지만 RoadNet 추정의 빈 구간은 직선으로 메우지 않는다. 강동02의 암사역 누락은 첫 패턴 20곳 이외의 두 번째 패턴 66곳을 연결해 보완했다. 같은 도로의 동일 유형 중복 선과 왕복 공통 경로는 한 선으로 정리하고, 다른 유형은 나란히, 방향별로 갈라지는 길은 연하게 표시한다. 선택 노선의 정차 번호는 활성 운행편 한 편의 `stop_sequence`이며 강동05는 1~59번이다.

로컬 실행에는 저장소 밖의 `bundles_v4/split/seoul_v4_1_network_gtfs_etc.zip`, `derived/d_bus_roads_gangdong_patterns_verified.geojson`, `derived/gbis_gangdong_official.geojson`을 각각 `--a-gtfs`, `--bus-geometry-file`, `--gyeonggi-geometry-file`에 지정하고 데이터 루트를 `--transit-data`에 지정한다. 예제와 SHA-256은 [도로 선형](d-roadnet-other-districts.md), [GBIS 선형](d-gbis-official-geometry.md)에 있다. 이 파일들은 PR에 포함되지 않으므로 팀원이 같은 지도를 재현하려면 별도 전달·재생성이 필요하다. 브라우저에서 사용자 사진과 같은 배율의 최종 시각 대조는 아직 완료하지 못했다. 관련 Python 테스트 27개와 지도 스크립트 문법 검사, 로컬 API 응답은 통과했다.

## 2026-11-25 추가 전달

실제 A GTFS 모드에 정상일 k5 버스 승하차와 선택 파업 노선 승차 노출량을 연결했다. **승차 노출량은 실제 전환·흡수·미충족이 아니다.** 지도 체크 중 시내·마을·경기버스만 버스 승차 노출을 다시 집계한다. 지하철 체크는 역 표시만 바꾸며 버스 수요원 계산에 넣지 않는다. A GTFS 버스는 검증을 통과한 외부 도로 선형만 표시하며, 선형이 없는 구간을 정류장 직선으로 채우지 않는다. 강동구에서는 p0/p1 왕복 운행 패턴을 확인해 마을버스와 시내버스가 같은 도로를 지날 때 유형별 선을 나란히 표시한다. 파업 노선 강조를 켜면 붉은 반투명 선으로 일반 색을 대체한다. 합성 DEMO는 가상 운행 조건을 다시 평가하며 저장된 B 결과는 기존 계산 범위를 유지한다. C의 `strike.py`·`absorb.py`는 역 접근 불가능 흐름에 한정되어 서울 전체 승차 노출량에 바로 차감할 수 없다. C/B는 같은 날짜·시간·망 버전의 등록부, 흐름·정원·M05 승객 결과·M07 검증을 제공해야 한다. 데이터 해시, ID 대조와 네 조건 비교는 [실제 교통 수요 문서](d-real-transit-demand.md)에 있다. 이번 수정은 로컬 작업이며 아직 커밋·Push·PR이 없다.

## 로컬 실행

저장소 루트에서 기본 명령 `py -3 web/operator/serve.py`를 실행하면 합성 DEMO가 열린다. A GTFS는 자동 탐색하지 않으므로 실제 ZIP을 `--a-gtfs`에 전달해야 A GTFS 모드가 활성화된다. 철도 실선도 필요하면 `--rail-gis-live` 또는 로컬 GeoJSON의 `--rail-gis-file`을 지정한다. 아래 경로를 각 PC의 실제 경로로 바꿔 실행한다. `/`와 `/simulation`은 동일한 통합 노선 실험실 레이아웃을 연다.

```powershell
py -3 web/operator/serve.py `
  --a-gtfs "C:\path\to\busstrike_data_release_20261111.zip" `
  --rail-gis-live `
  --transit-data "C:\path\to\seoul_transit_data.Zip" `
  --simulation-results "C:\path\to\routegen_v4" `
  --simulation-inputs "C:\path\to\region_bundles_v4"
```

`--transit-data`는 `TRANSIT_DATA_ROOT` 환경변수로도 지정할 수 있다. 미지정 시 사용자 Downloads의 `seoul_transit_data` 폴더 또는 ZIP을 탐색한다. `--simulation-results` 아래에는 `<구>/manifest.json`, `candidates/*.json`, `plans/*.json`, `runs/<variant>/runs.json`, `runs_test/<variant>/runs.json`, 각 실행의 `run/metrics.json`, `run/passenger_outcomes.csv`, `verifier_report.json`, `plan_m05.json`이 필요하다. `--simulation-inputs` 아래에는 `<구>_0610_v4/network/stops.csv` 및 `network/travel_times.json`이 필요하다. 원본 배치는 [시뮬레이션 계약](d-simulation-contract.md)에 적었다.

## 화면 해석과 참고사항

- 수요 입력의 시간은 **06:00~10:00**이다. `bin_start_s=21600,25200,28800,32400`, 각 `bin_width_s=3600`이며 24시간 자료가 아니다.
- 네 변형 `affected`, `affected_maeul`, `affected_gg`, `affected_maeul_gg`는 C의 `maeul_reach`·`gg_reach` 흡수 가능 수요 제외 조건이다. 결과 화면의 별도 **저장된 결과 조회 조건**에서 마을·경기버스 운행 여부를 바꾸면 해당 저장 결과를 선택한다. 지도 표시 체크는 원·선만 숨긴다. 시내버스·지하철 중단 변형은 없어 해당 운행 조건을 바꿔도 수요·충족률은 재계산되지 않는다. A GTFS + k5에서는 파업 노선 승차 노출만 계산한다.
- **관측 승차(k5)**, **셔틀 투입 전 파업 잔여 수요**, **M05 셔틀 투입 후 미충족 수요**는 서로 다르다. 시뮬레이션 기본 빨간 원은 입력 번들의 잔여 수요다. 해당 날짜의 `passenger_outcomes.csv`가 연결되면 출발 정류장별 M05 미충족 원으로 바뀐다. 총 충족률을 정류장별로 임의 배분하지 않는다.
- 보고서 충족률은 `M1 served / M1 total`이며 분모는 선택한 실행의 잔여 수요다. 구·시나리오·기간마다 분모가 달라 직접 비교할 때 조건을 같이 본다. 5일 평균 보고서 값과 개별 날짜 M05 원본은 화면에서 출처를 나눈다.
- 지도 표시 옵션의 `잔여·미충족 수요 원`으로 원을 끄고 켠다. 조건 변경 시 원 반지름을 약 0.5초 보간한다. M05 공간 결과가 양쪽 조건에 있으면 달라진 정류장을 굵은 테두리로 강조한다.
- A GTFS에는 `shapes.txt`가 없다. A 버스 선은 `--bus-geometry-file`의 검증된 외부 경로가 있을 때만 그린다. `roadnet_pattern_estimate`는 OSM 도로망 추정이며 공식 운행 선형이 아니고, 확인되지 않은 구간은 비워 둔다. C 노선의 검증된 도로 선형이 없으면 실제 운행 경로로 표시하지 않는다. A/C 정류장 ID도 자동으로 동일시하지 않는다.
- M07의 `pass=true`는 `fully_verified=true`와 다르다. 선택 실행의 실패·미실행·미검증 검사와 입력 버전을 함께 확인한다. 화면의 운행안 `selected`는 실제 운행 승인이나 시민 안내 확정이 아니다.

## PR에 포함할 것과 외부 인수물

PR 비교에는 운영자 화면/API, `web/operator/vendor/`의 MapLibre 파일과 라이선스, 25개 자치구 경계 자료·생성기, D 테스트·문서가 포함된다. 현재 worktree의 `web/operator/data/districts.geojson`은 런타임에서 사용하지 않는 기존 미추적 파일이므로 별도 확인 없이 PR에 넣지 않는다. `seoul_transit_data.Zip`, A 배포 ZIP, 원본 카드 자료, `.keys`, 재계산 실행 파일과 개인 식별자는 PR에 넣지 않는다. 외부 자료는 읽기 전용 경로로 연결한다.

네 구 전체의 차량·운행안별 빨간 원을 보려면 C/B팀에서 PR #41 실행 결과 루트 전체를 받아야 한다. 특히 구별 `manifest.json`·계획·후보, 실험/테스트 `runs.json`, 각 실행의 `metrics.json`·`passenger_outcomes.csv`·`verifier_report.json`·`plan_m05.json`, 일치하는 `network_snapshot_id`의 정류장 좌표·이동시간 자료가 필요하다. `passenger_outcomes.csv`는 로컬에서만 읽어 출발 정류장별로 집계하며 승객 ID를 API로 반환하지 않는다. 공용 서비스로 배포하려면 별도의 비식별 집계본과 접근 통제가 필요하다.

## 이번 GIS 선형 추가와 팀 공유 자료

`--rail-gis-live` 또는 `--rail-gis-file`을 지정하면 검증을 통과한 철도 물리 선형을 표시한다. 서울 버스는 현재 로컬 데이터의 `--bus-geometry-file`에서 130개 선형을 매핑한다. 이 중 9개는 강동구 OSM 도로망과 A GTFS의 왕복 운행 패턴으로 만든 `roadnet_pattern_estimate`이며, 공식 버스 운행 선형은 아니다. 별도 GBIS 파일 `--gyeonggi-geometry-file`에는 경기버스 공식 선형 23개가 있다. 강동구에서 확인된 자료와 재현 명령은 [왕복 패턴 도로 선형 문서](d-roadnet-other-districts.md)와 [GBIS 선형 문서](d-gbis-official-geometry.md)에 적었다. 원본 ZIP·도로망·생성 GeoJSON은 저장소 밖에 있으며 PR에 포함되지 않는다.

팀원이 최종 운영자 화면을 재현하려면 PR 코드 외에 별도 로컬 공유가 필요하다: (1) A GTFS 배포 ZIP, (2) `seoul_transit_data.Zip` 및 문서상 허용된 접근 권한, (3) 4개 구의 C/B/M07 원본 결과 전체 트리와 동일 버전의 `region_bundles_v4` 입력, (4) 오프라인 철도 GIS를 쓰려면 공식 레이어에서 받은 GeoJSON과 재사용 조건, (5) 버스 실선이 필요하면 OA-15264 또는 T-DATA 1056/1058 인증키를 각자 환경변수로 발급받고 노선 ID·정류장 순서 매핑 표를 확보해야 한다. `.keys`, 원시 카드 자료, 대용량 ZIP 및 실행 결과 원본은 PR에 올리지 않는다. `passenger_outcomes.csv`가 없는 실행은 정류장별 빨간 미충족 수요 원을 정확하게 만들 수 없다.

지하철역은 노선 선택과 관계없이 줌 9 이상에서 보라색 열차 아이콘과 역 이름을 함께 표시한다. `지하철역` 레이어를 끄면 아이콘과 이름이 함께 숨겨진다. 버스 정류장은 시내 파랑·경기 주황·마을 초록으로 표시한다. 같은 정류장에 여러 유형이 서면 유형별 아이콘을 조금 비켜 각각 그린다. 노선을 선택하면 A GTFS의 활성 운행편 중 가장 긴 정차 순서를 번호로 표시하며, 왕복 재방문에도 새 번호를 매긴다.

잔여·미충족 수요 원과 시뮬레이션 노선은 정류장·역 아이콘보다 아래에 그린다. 역 이름도 수요 원 위에 유지하고, 같은 위치를 클릭하면 역·정류장 팝업을 우선한다. A GTFS 로더가 경기 노선을 경기 유형으로 분류하지 않은 경우에는 주황 정류장이 나타나지 않으며, 이를 임의 분류하지 않는다.

수동 확인: `py -3 web/operator/serve.py --a-gtfs "<A GTFS ZIP 경로>" --rail-gis-live`로 실행한다. `http://127.0.0.1:8766/`에서 합성 DEMO/A GTFS 전환, 시뮬레이션 결과 표시 토글, 좌측 패널 접기, 구 선택, 레이어 토글, 노선 선택·정류장 강조를 확인한다. 실제 C/B 결과 루트가 연결되지 않으면 노선·차량 배분은 미연결로 표시되어야 한다.

## 노선 실험실 UI 통합 메모

합성 DEMO·A GTFS·시뮬레이션 결과가 모두 하나의 노선 실험실 지도 레이아웃을 공유한다. 상단 데이터 모드 선택은 DEMO/A GTFS를 전환하고 `시뮬레이션 결과 표시`는 현재 교통망 모드를 유지한 채 결과 오버레이를 켜고 끈다. 자치구 선택은 상단에 두고, 왼쪽 접이식 패널에 노선 목록·레이어·기존 운행 조건 및 상세 패널을 배치한다. 비교·M07·운행안 선택 이력은 기존 `/api/d/simulation/*` 계약을 사용한다. 개인 실험실 생성·재실행 API는 연결하지 않으며, 결과가 없어도 노선이나 수치를 만들어 내지 않는다. 실제 도로 geometry가 없는 계획은 정류장 순서 실선 개략도로 표시하고 도로 경로가 아님을 안내한다. A GTFS가 미연결이어도 선택 구 경계를 보이도록 25개 경계 파일을 `/data/districts_all.geojson`으로 제공한다. 새 UI 동작의 API·브라우저 검증 여부는 실제 테스트 기록에 구분해 적는다.

합성 DEMO의 파업 복구·수단 제외·셔틀 경로/차량·가상 날짜/시간 변경은 `POST /api/d/demo/scenario/evaluate`에서 다시 배분한다. 파업 복구는 OD를 지우지 않고 복구 노선의 정차 순서·가정 정원으로 수송한다. 이 계산은 C M05/B M07의 실제 결과가 아니다. 재현 스크립트, 데이터 해시, 공식 외부 자료 조사 및 미연결 사유는 [D 시나리오 재현 문서](d-scenario-reproducibility.md)에 적었다.
