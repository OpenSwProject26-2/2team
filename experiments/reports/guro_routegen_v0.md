> 이 문서는 `experiments/guro_routegen/make_report.py`가 생성 결과(`manifest.json`, `candidates/*.json`, `bundle_check.json`)와 실행 결과(`runs.json`, 실행별 `metrics.json`·`timetable.json`·`passenger_outcomes.csv`)를 읽어 만든다. 숫자를 손으로 고치지 않는다. 실행 원본·plan.json·후보 목록은 저장소 밖에 있고 커밋하지 않는다.

- 설계 v1 4절(후보 노선 생성)·5절(구별 예산 제약 배분) 중 **구로구 하나, per_gu**만 구현해 운행안 16개(우리 알고리즘안 8개 + 비교 기준 최단경로 피더안 8개)를 만들고 각 안을 해당 변형·차량 조건의 5일 묶음으로 돌렸다.
- 실행 80회 중 변환기 S1–S6 통과·M05 완료·M07 pass 80회, 실패 0회.
- **파라미터는 기본값 그대로다.** 결과를 보고 바꾼 값은 없다(§7).
- 시뮬레이터 충족률(5일 합 기준) 우리 안 / 최단경로 피더안: `affected` 11대 12.0% / 11.8%; `affected` 13대 13.8% / 13.3%; `affected_maeul` 11대 12.9% / 12.9%; `affected_maeul` 13대 14.0% / 14.0%; `affected_gg` 11대 13.1% / 12.9%; `affected_gg` 13대 14.5% / 14.5%; `affected_maeul_gg` 11대 14.0% / 14.0%; `affected_maeul_gg` 13대 14.6% / 14.6%.

## 2. 후보 생성

### 2.1 파라미터(기본값)

| 항목 | 값 |
|---|---|
| F_min = 2 × 좌석 × (240 ÷ C₀) | 2 × 45 × (240 ÷ 40) = 540명(4시간 합, 5일 평균) |
| 권역 반경 R | 3.0 km (역 좌표 ↔ 정류장 좌표 직선거리) |
| 겹침 τ / 군집 상한 / 넘칠 때 τ 증가 폭 | 0.2 / 역 3개 / 0.05 |
| 섹터 수 m · 편도 상한 L_max | {2, 3, 4} · {20, 30}분 |
| 정차 상한(역 지정 정류장 제외) · 우회율 상한 | 8개 · 1.6 |
| 최단경로 피더 seed | 허브·방향마다 수요 상위 15개 |
| 중복 제거 | 같은 방향끼리 정차 정류장 Jaccard ≥ 0.8 |
| 배분 대기 W · κ | 1200초 · 1.0 |

구현에서 정한 해석(설계 문서에 값이 없는 곳):

- F_k와 권역 수요 r(s↔k)는 access와 egress를 더한다.
- 편도 = 06~09시 프로필마다 Σ 구간 시간을 따로 잰 최댓값 + 기본 정차 × 구간 수(시뮬레이터 `planned_cycle`의 영업 leg와 같은 정차 규칙).
- 정류장 사이 최단경로의 가중치도 구간 프로필 최댓값. 경로 위 정류장은 모두 정차로 센다(통과 정류장 표현 없음).
- 우회율 = 노선 경로 길이(망 구간 거리 합) ÷ 첫 정류장–끝 정류장 직선거리. 망 구간 거리도 정류장 좌표 직선거리다(README).
- 섹터: 중심(허브 역, 연결은 두 역의 중점)에서 본 방위각 순으로 늘어놓고 가장 큰 빈 각에서 시작해 수요가 거의 같은 m조각. seed = argmax v_s × dist(s, 중심). seed는 혼자서 제약을 지키는 정류장만 후보로 둔다.
- 삽입 점수 = 증가 덮개 수요 ÷ 증가 편도 시간(시간이 늘지 않으면 무한대). 덮개 수요는 노선이 덮는 모든 OD(다른 역 포함).
- 2-opt: 고정 끝(역 정류장)을 뺀 anchor 구간 뒤집기를 한 번 훑는다. 편도가 줄고 덮개가 줄지 않을 때만 받는다.
- 최단경로 피더도 같은 제약(L_max는 큰 값 30분)을 지키는 seed 중 상위 15개.
- 중복 제거는 같은 방향(kind + 고정 역 정류장)끼리만 비교한다. access A→역과 egress 역→A는 정류장 집합이 같아도 다른 승객을 태운다. 역 ID가 아니라 정류장으로 보므로 지정 정류장을 같이 쓰는 역(온수 1821·2752)의 같은 노선은 하나로 합쳐진다.
- 우리 안의 후보 풀 = 생성 + 최단경로 피더를 함께 넣고 중복 제거, 비교 기준 풀 = 최단경로 피더만 중복 제거.

## 9. 관찰과 한계

- **삽입 휴리스틱이 최단경로 피더와 거의 같은 노선을 낸다.** 생성 후보 203개 중 166개가 피더와 정차열이 같다. 삽입 시도 16,368회 중 제약을 지킨 것은 8.8%(1,447회)이고, 거절 사유는 경로 없음·S2, 정차 수, 우회율, 편도가 비슷한 크기로 나온다(§2.4 제약 판정 집계). 망은 정류장 1,407개·구간 1,858개(정류장당 나가는 구간 평균 1.32개)이고 경로 위 정류장을 모두 정차로 센다. 통과 정류장 표현(설계 수정 제안 1번)이 정해지면 정차 수 제약이 풀려 이 결과가 달라질 수 있다.
- **우리 안의 후보 풀은 피더 풀의 정차열을 모두 포함한다**(피더 풀에만 있는 정차열 0개). 같은 정차열이 생성·피더 둘 다에서 나오면 중복 제거에서 생성 쪽 이름으로 남는다. 그러므로 피더안은 우리 풀에서도 고를 수 있는 안이다.
  - `affected` 13대: 근사 값 우리 안 2,479.8 < 피더안 2,493.1. 피더안의 노선은 모두 우리 풀에 있으므로 이 차이는 **CELF 탐욕 + 국소 탐색(1대 옮기기·노선 닫고 재배분)이 국소해에 멈춘 것**이다. 근사 목적함수에서도 우리 배분기가 더 나은 안을 놓쳤다.
- 국소 탐색이 받아들인 이동: 안 16개 합 0개. 탐욕 직후 값 = 최종 값인 안 16/16개.
- 근사는 대기 한도·수송 한도만 보고 운영 종료(service_end), 만차 대기열, 날짜별 정수화를 모른다. 안 16개 합으로 근사 − 시뮬레이터 = 4,622.7명, 같은 안의 service_end + wait = 4,956.6명(§4 표). 운영 종료 규칙이 바뀌면 κ를 다시 구해야 한다.
- 겹침 지표 O가 R = 3 km에서 포화한다(§2.3). 병합을 의미 있게 쓰려면 R을 줄이거나 O를 min(F) 대신 F_i + F_j로 나누는 정규화를 검토한다. 이번에는 바꾸지 않았다.
- 편도 연결은 seed 판정 5,322회 중 4회만 통과해 후보가 2개뿐이고, 운행안에 쓰인 연결 노선은 0개다. 거절 중 경로 없음·S2가 3,152회로 가장 많다(역 i egress 정류장 → 정류장 → 역 j access 정류장이 30분 안 망 경로로 안 이어지거나 정류장이 겹침). 나머지는 편도·정차 수·우회율이 함께 걸린다.
- 순환·양방향 영업은 만들지 않았다(비교 입력 S2, 엔진의 영업 leg 1개 제약).
- 파업 노선 등록부 v0, 구간시간 기간(9/21~10/25) ≠ 수요 기간, 경기 흡수 낙관적 근사, 대기·이동 한도 승인 전 — 입력 묶음의 한계는 이전 보고서(`guro_exp_1026_30.md` §6)와 같다.
