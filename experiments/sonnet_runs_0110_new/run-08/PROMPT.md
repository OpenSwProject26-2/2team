# 구로구 버스 파업 대체 셔틀 설계 실험

## 이번 회차의 과제

서울 구로구에서 시내버스가 파업했다. 출근 승객이 집 근처 정류장에서 셔틀을 한 번 타고 철도역으로 이동한 뒤, 철도로 최종 목적지 역까지 갈 수 있도록 **운행안 하나**를 설계하라. 노선별 정류장 방문 순서와 차량 대수를 정하고, 결과를 한국어로 제출하라.

**입력: 도입 가능 차량 = 11대.** 차량 수는 운영자가 실험 조건으로 지정한다. 이 문서에서는 11대를 모두 배분한다. 대수가 바뀐 별도 실험에서는 노선과 노선별 배분을 새로 정할 수 있다. 개별 출발 시각은 제출하지 않는다. 평가자가 모든 안에 같은 규칙으로 시간표를 만든다.

## 사용할 자료

첨부된 네 CSV만 사용하라. ID는 앞자리 0을 보존하는 문자열로 읽고, 수요는 행 수가 아니라 `people`의 합으로 계산하라. 파일 분석과 로컬 계산은 허용한다. 웹 검색, 외부 지도·시간표, 기존 운행안, 다른 회차 답안, 프로젝트 저장소나 평가기에는 접근하지 않는다. 파일을 열 수 없다면 빠진 파일명을 알리고 중단한다.

| 파일 | 읽을 내용 |
|---|---|
| `stops.csv` | 셔틀이 방문할 수 있는 정류장의 ID, 이름, 위도·경도 |
| `stations.csv` | 목적지 철도역의 ID, 이름, 위도·경도 |
| `demand.csv` | 출발 정류장, 목적지 역, 출발 시간대, 하루 평균 인원, 목적지의 철도망 포함 여부 |
| `access.csv` | 정류장에서 500m 안에 있는 철도역과 도보 시간(초), 거리(m) |

## 평가 기준과 제약

- **시간 보조지표(v2): 0~90분 평균 누적 수요충족률.** 같은 수요가 더 일찍 목적지에 도착할수록 높다. 승객별 출발부터 최종 목적지 도착까지 걸린 시간을 T(초)라 할 때 점수(%)는 100 × Σ max(0, 5400 − T) / (5400 × 16230)이다. 미도착자는 0으로 기여하며 분모에는 남는다. 정확히 90분에 도착하면 주지표에는 성공, 이 지표에는 0으로 기여한다. 주지표를 우선하되 이 보조지표도 함께 고려하고, 제출 메모에 빠른 도착과 전체 도착 인원 사이에서 내린 선택을 한 줄 적어라. 실제 점수와 곡선은 평가자가 계산한다.
- **주지표:** 전체 16,230명 중 출발 후 **90분 이내에 최종 목적지 역에 도착**하는 인원을 최대화한다. 총시간에는 승차 전 보행, 대기, 셔틀 이동, 하차 후 보행, 철도 이동과 환승 부담이 포함된다.
- **대기 보조지표:** 전체 승객 중 **셔틀 정류장 도착 후 10분 이내에 탑승하고, 출발 후 90분 이내에 목적지에 도착**한 비율도 본다. 10분을 넘겨도 아래의 최대 대기 조건을 충족하면 주지표에는 포함될 수 있다.
- **권역 형평성:** 출발 정류장에서 가장 가까운 철도역을 기준으로 권역을 나눈다. 수요 100명 이상 권역 중 최저 도착률과, 도착률 10% 미만인 권역들의 전체 수요 합을 함께 본다. 확보하기 어려운 권역은 이유를 설명한다.
- 차량은 45인승이며 입석은 없다. 운행 가능 시간은 06:00~10:00, 승객 출발 시간은 07:00~09:00이다. 승객은 각 보행 구간에서 직선 500m까지 걸으며 셔틀을 최대 20분 기다린다. 만차면 이 한도 안에서 다음 차를 기다린다. 셔틀 간 환승은 허용하지 않는다.
- 노선마다 실제 `stop_id`가 2개 이상 있어야 한다. 같은 정류장의 연속 중복은 금지하되 회차 후 재방문은 허용한다. 각 노선에 양의 정수 대수를 배분하고 총합을 입력 대수와 맞춘다.
- 미수송 수요를 삭제하지 않는다. `rail_known=0`인 829명은 전체 분모에 남지만 도착으로 인정되지 않는다. 최종 성적은 평가자가 동일한 시뮬레이터로 계산한다.

## 제출할 결과

1. **`sonnet-run-08.json`**: 최상위 객체에 `routes` 배열을 둔다. 각 원소는 `route_id`(고유 문자열), `stops`(방문 순서대로 나열한 정류장 ID 문자열 배열), `vehicles`(배분 대수) 세 필드를 가진다. JSON에는 주석이나 설명을 넣지 않는다.
2. **`sonnet-run-08.md`**: 노선마다 “출발 지역 → 환승시킬 철도역 / 차량 대수 / 선택 이유”를 한 줄로 쓴다. 이어서 충분히 서비스하지 못한 수요·권역, 판단 이유, 자료에 없어 가정한 값을 짧게 적는다.
3. 제출 전에 입력 CSV 기준으로 정류장 ID, 연속 중복, 차량 대수와 총합을 확인한다. 채팅 답변에는 **노선 수·배분 대수 합계·검사 결과**를 알린다. 공식 도착률이나 비교 순위를 추측하지 않는다. 파일 생성이 불가능하면 두 파일의 전체 내용을 파일명별 코드 블록으로 반환한다.

이번 제출 ID: sonnet-run-08. 파일은 현재 회차의 `결과/` 폴더에 저장한다. 기존 제출물은 덮어쓰지 않는다. 파일 첨부 환경에서는 같은 이름으로 반환한다.
