# 운행안 변환 규칙

출처가 다른 운행안을 **같은 입력 형식**으로 바꾼다. 규칙은
`docs/design/evaluation-protocol.md` §3·§4를 따른다.

변환은 평가의 일부다. 해석이 들어간 지점은 전부 `conversion.md`에 적는다. 같은 원본을 다르게
변환하면 결과가 달라지기 때문이다.

## 1. 비교 입력 `plan.json`

운행안이 주는 것은 **노선과 노선별 차량 수뿐**이다. 배차 시각은 모든 안에 같은 생성기가
만든다(프로토콜 C3). 안이 배차 시각을 직접 제안했더라도 비교에는 쓰지 않고
`conversion.md`에 기록만 한다.

```json
{
  "plan_id": "plan-01",
  "revision": 1,
  "network_snapshot_id": "...",
  "routes": [
    {"route_id": "r1", "stops": ["S0003", "S0007", "S0011"], "vehicles": 4}
  ]
}
```

| 필드 | 규칙 |
| --- | --- |
| `plan_id` | 출처를 드러내지 않는 이름(`plan-01`). 비교 전에는 어느 안인지 모른다 |
| `revision` | 내용이 바뀌면 올린다. 같은 `(plan_id, revision)`의 내용은 불변 (M00 §3.3) |
| `network_snapshot_id` | 모든 안이 같은 값을 쓴다 (프로토콜 C6) |
| `routes[].stops` | **방문 순서대로** 쓴 정류장 ID. 망에 있는 ID만 |
| `routes[].vehicles` | 그 노선에 배정할 차량 수(정수) |

- 모든 안의 `sum(routes[].vehicles)`가 같아야 한다 (프로토콜 C2). 다르면 비교하지 않는다.
- 출처·설명·주석을 넣지 않는다. 그것은 `manifest.json`과 `conversion.md`에 있다.
- 양방향 운행은 노선 2개로 쓴다. 한 노선에 왕복을 담지 않는다.

## 2. 출처별 변환

### 2.1 지자체안

| 단계 | 할 일 |
| --- | --- |
| 수집 | 출처 URL·수집일·자료 형태를 기록 |
| 정류장 매칭 | 자료의 정류장 이름 → 우리 망의 정류장 ID. **매칭 규칙과 실패 건수를 기록** |
| 노선 방향 | 상·하행을 노선 2개로 분리 |
| 대수 | 자료에 있으면 그대로. 없으면 **"미상"** 으로 두고 임의로 추정하지 않는다 |

정류장 이름만으로 전역 고유키를 만들지 않는다(M00 §2.1). 같은 이름의 다른 정류장이 있다.
매칭하지 못한 정류장은 노선에서 빼지 말고, 그 노선을 **변환 실패**로 처리할지 일부만 쓸지
`conversion.md`에 정하고 적는다.

### 2.2 범용 AI안

| 단계 | 할 일 |
| --- | --- |
| 입력 고정 | 세 모델에 같은 프롬프트·같은 망 정보·같은 차량 수·같은 정책을 준다 |
| 출력 보존 | 원문 그대로 `source/`에 저장. 변환 전에 손대지 않는다 |
| 변환 | 출력에서 노선·대수만 뽑는다 |
| 검사 | 아래 §3 검사를 통과해야 `plan.json`이 된다 |
| 실패 | 통과하지 못하면 **변환 실패**로 기록. 모델에 다시 물어 고치지 않는다 |

마지막 줄이 중요하다. 모델에 다시 물어 고치면 그 안만 사람 손을 더 받은 것이 되어 비교가
공정하지 않다. 재시도를 허용하려면 **모든 안에 같은 횟수**를 허용하고 규칙을 먼저 적는다.

AI가 망에 없는 정류장을 지어내는 경우가 흔하다. 그 노선은 검사에서 걸린다. 지어낸 정류장을
가까운 실제 정류장으로 **우리가 바꿔 주지 않는다.** 바꿔 주면 우리가 그 안을 고쳐 준 것이다.

### 2.3 우리 알고리즘안

`busstrike.planning`의 출력을 변환한다. 코드 커밋과 입력 설정을 기록하고, 2회 실행해 같은
출력이 나오는지 확인한다.

## 3. 변환 결과 검사

`plan.json`이 되기 전에 전부 통과해야 한다.

| 검사 | 내용 | 실패 시 |
| --- | --- | --- |
| S1 정류장 존재 | 모든 정류장 ID가 망에 있다 | 변환 실패 |
| S2 중복 없음 | 한 노선 안에 같은 정류장이 두 번 나오지 않는다(순환 노선은 별도 규칙) | 변환 실패 |
| S3 길이 | 노선당 정류장 2개 이상 | 변환 실패 |
| S4 구간 존재 | 연속한 두 정류장 사이 이동시간이 망에 있다 | 변환 실패 |
| S5 대수 | `vehicles ≥ 1`인 정수. 합이 가용 대수와 같다 | 변환 실패 |
| S6 노선 ID | 안 안에서 유일하다 | 변환 실패 |

S4가 실패하는 운행안은 "이동시간을 모르는 구간"을 쓰는 것이다. 0초나 직선거리로 메우지
않는다(M00 §2.2).

## 4. `conversion.md` 에 적을 것

```markdown
# plan-0N 변환 기록

- 원본: source/...
- 변환일:
- 변환한 사람:

## 해석이 들어간 지점
- (예) 원본의 "○○역앞" 을 S0123 으로 매칭. 같은 이름 정류장 2개 중 상행 쪽을 택함
- (예) 원본에 대수가 없어 노선당 균등 배분함

## 검사 결과
- S1~S6: 통과 / 실패(사유)
- 매칭 실패 정류장: N개 (목록)

## 버린 것
- (예) 표본 2는 S1 실패(망에 없는 정류장 3개)로 변환 실패
```

해석 지점이 하나도 없으면 "없음"이라고 적는다. 비워 두지 않는다.

## 5. 미정

- 순환 노선(같은 정류장 재방문) 허용 여부와 S2 예외 규칙
- 망에 없는 정류장을 AI가 지어냈을 때, 노선 전체를 버릴지 그 정류장만 건너뛸지
  — **현재는 노선 전체를 변환 실패로 둔다.** 건너뛰기를 허용하면 우리가 안을 고치는 것이 된다
- 지자체안 자료 형식을 확인한 뒤 §2.1을 구체화한다
