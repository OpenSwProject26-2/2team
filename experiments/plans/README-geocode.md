# 임시 정류장 좌표 구하기

셔틀 전용 임시 정류장은 기존 정류장 망에 없다. ARS 번호도 정류장 ID도 없고 노선도에
**주소만** 적혀 있다. 그 주소를 좌표로 바꿔 망에 추가한다.

가까운 기존 정류장으로 **대체하지 않는다**. 대체하면 우리가 노선을 바꾼 것이 된다
(의사결정 `docs/design/evaluation-decisions.md` M-01).

## 실행

```sh
export KAKAO_REST_KEY='...'          # 저장소·커밋·프롬프트에 넣지 않는다
export GEOCODE_DATE='2026-11-16'     # 조회일. 출처 기록에 들어간다
python3 experiments/plans/geocode_stops.py plan-01 --dry-run   # 조회할 주소만 확인
python3 experiments/plans/geocode_stops.py plan-01
```

입력·출력은 `<plan>/source/temporary-stops.json`이다. 받은 좌표를 **검토 대기 상태로**
적고, 사람이 확인한 뒤 `plan.json`에 반영한다. 이 도구는 `plan.json`을 고치지 않는다.

주소 2곳 정도면 지도에서 직접 읽는 편이 빠르다. 자치구를 넓혀 임시 정류장이 늘어날 때
쓰려고 만들었다.

## 키

카카오 개발자 사이트에서 앱을 만들면 REST API 키가 나온다. 호출이 거부되면 앱의
**카카오맵 사용 설정**과 **일일 호출 한도**를 먼저 본다. 키를 저장소에 넣지 않는다
(`AGENTS.md` 금지 항목).

## 이 도구가 하지 않는 것

| | |
| --- | --- |
| 후보가 둘 이상일 때 고르기 | `needs_review`로 표시하고 후보를 전부 적는다 |
| 반환 주소가 입력과 다를 때 그대로 쓰기 | 둘 다 적고 표시한다 |
| 범위를 벗어난 좌표 고치기 | 표시만 한다. 값을 바꾸지 않는다 |
| `plan.json` 수정 | 사람이 확인한 뒤 따로 한다 |

## 두 겹으로 거른다

### ① 주소 대조

반환된 도로명주소가 입력과 **같은 길·같은 번호**인지 본다.

| 입력 | 반환 | 판정 |
| --- | --- | --- |
| 디지털로27길 33 | 디지털로27길 33 (구로동) | 통과 |
| 디지털로27길 33 | **디지털로27라길** 33 | 표시 |
| 디지털로27길 33 | 디지털로27길 **331** | 표시 |

### ② 노선 구간 범위

노선 순서상 앞뒤 정류장을 잇는 경로에서 크게 벗어나는지 본다.

| 좌표 | 우회 | 판정 |
| --- | --- | --- |
| 구간 한가운데 | +0 m | 통과 |
| 1.5 km 밖 | +1,315 m | 표시 |
| 강남 한복판 | +23,739 m | 표시 |

**범위 검증은 큰 오류만 잡는다.** 같은 동네의 다른 길은 수십 미터 차이라 통과한다
(`디지털로27라길`이 +26 m로 통과했다). 그래서 ①을 함께 쓴다.

## 좌표의 성격

API가 주는 것은 **건물 위치**다. 임시 정류장은 그 앞 도로변이라 수십 미터 차이가 날 수
있다. 그래서 상태를 **`주소 기반 추정 — 검토 대기`** 로 적고, 출처·조회일·입력 주소·반환
주소를 함께 남긴다.

더 정확한 값이 필요하면 구로구 교통행정과(02-860-2475)에 실제 위치를 확인한다.

## 다른 선택지

| | |
| --- | --- |
| 브이월드 지오코더 (국토교통부) | 공공 무료. 보고서에 공공 출처를 쓰고 싶을 때 |
| 도로명주소 개발자센터 좌표제공 API (행정안전부) | 주소 원천 기관. 좌표계 변환이 필요할 수 있다 |

둘 다 문서를 확인하지 않았다. 쓰기 전에 좌표계와 신청 조건을 확인한다.
