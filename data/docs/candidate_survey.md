# 소규모 실제 교통망·수요 추출 후보 조사

공식 지역·파업 중단 노선을 정하지 않는 탐색 작업이다. 원본 ZIP·시간대 전체 OD는 읽지 않고 기존 분석 결과, 오전 OD, 정류장 방문열과 노선 버전 자료만 사용한다. 기존 분석 출력과 stash를 보존한다.

```powershell
python -B -m unittest discover -s tests -t . -v
python -B -m data.candidate_survey --input-dir raw/from_teammate --analysis-dir data/processed/taims_demand --output-dir data/processed/taims_candidate_survey
```

새 출력 디렉터리를 지정한다. 실제 상세 자료는 Git 제외 경로에만 저장하며 공개 가능성을 확정하지 않는다. `survey.json`, `report.md`, `comparison.csv`, `pairwise.csv`, `group_quality.csv`, `source_visits.csv`를 생성한다.

## 선정·비교 기준

기존 상위 승하차 정류장과 OD를 근거로 미아리고개(`107000005`), 구로디지털단지역(`120000001`), 선릉역(`122000156`)을 비교용 허브로 삼는다. 같은 장소처럼 보여도 다른 정류장 ID는 합치지 않는다. 각 정확한 ID를 방문하는 노선 중 오전 전체 인원 상위 최대 5개를 선택하며 3개 미만이면 묶음을 만들지 않는다. 전국 최적 후보 탐색이나 확정 지역 선정은 아니다.

공유 정류장은 원천 노선별 ID 집합의 교집합이다. 연속 공유 구간은 **같은 노선 ID+노선명 그룹 안에서 원천 순번이 연속되고 정류장 ID 배열이 같은** 부분열이다. 허브를 포함하는 최장 부분열을 노선 모두/노선쌍별로 찾으며 모든 매칭 그룹과 원천 순번을 기록한다. 순번 공백·한 순번의 서로 다른 정류장은 연결하지 않고 끊는다. 중복 행이 같은 순번·정류장이면 방문 증거를 접되 원천 행 수를 보존한다. 같은 정류장의 다른 순번 방문은 유지한다. 중복을 모두 공동운행으로 해석하지 않는다.

이 결과는 원천 순서상 같은 방향의 증거이며 실제 방향·유효 버전·운행 가능한 연결의 확정이 아니다. 미확인 주행시간·회전·회차는 추정하거나 0초로 채우지 않는다. 현재 C의 재방문·동일 거점 제약에 맞추려고 실제 입력을 바꾸지 않는다.

오전 CSV는 행 단위로 읽으며 인원은 PSNG_NUM 합계다. 노선별 전체 합계를 먼저 구하고 선택 노선에 대해 같은 그룹의 승차 순번 < 하차 순번인 방문 쌍 수를 센다. 회사 등 중복 행은 같은 순번·정류장의 쌍을 증식시키지 않는다. 0개/1개/여러 개의 **원본 집계 행 수와 가중 인원**을 기록한다. 후보 1개는 방향 판별 정확도가 아니다.

묶음 수요는 해당 노선들의 **전체 오전 인원**이다. 별도 허브 끝점 수요는 승차/하차 중 하나가 정확한 허브 ID인 기록, 공통 구간 끝점 수요는 그중 하나가 공유 원천순서 구간 ID 집합에 속하는 기록이다. 해당 구간을 실제 통과한 전체 수요·지역 전체 수요를 의미하지 않는다. 후보 사이 중복 노선·수요는 합산하지 않는다. 상위 OD 기여도는 같은 승하차 ID 쌍에 해당하는 후보 노선의 인원만 세며 전체 상위 OD 인원과 구분한다. 상위 OD의 길이는 가정하지 않는다.

관측일은 기존 보고서에서 가져온다. START_DE <= 관측일 <= END_DE의 양끝 포함 비교를 가정하고 99991231은 비교상 미래 종료일로 취급한다. 공식 경계 규칙·버전 의미는 미확정이며 latest는 표시 참고다. 그룹명과 유효 버전 이름의 일치 여부도 별도로 기록한다. 이름·좌표는 기존 분석과 같은 후보 집합 방식이며 임의로 대표를 확정하지 않는다. 서울 외·미확인 여부는 원천 SIDO_NM 기준이며 독립 행정경계 검증은 아니다.

추천은 수요 규모, 허브 통과 공통 원천순서 구간 길이, 0개/여러 개 순서후보 인원 비중의 동일 가중 순위합으로 비교한다. 동률은 해당 비중이 작은 후보를 선택한다. 이는 탐색적 휴리스틱이며 팀 정책·실제 운행 정확도·C 연결 용이성 기준이 아니다. 추천에도 그룹별 반복·충돌·유효성·행정구역과 부족 자료를 함께 검토해야 한다.

## 검증과 후속

관측 기준일은 자료 설명의 기준이며 다음 날짜 승차 기록의 서비스일 귀속까지 검증했다는 뜻은 아니다. 시 단위 정리본으로 날짜 귀속을 재구성하지 않는다. 후보 조사 결과는 B·C의 최종 실행 입력이 아니다.

방문 순번은 양수 ASCII 정수로 검사하며 잘못된 값은 파일·줄 번호·필드명만 알린다. 노선 유효기간의 잘못된 달력 날짜는 유효 행으로 세지 않고 미확정으로 남긴다. CLI의 예상 입력 오류는 종료 코드 2로 처리하고 원천 값·행·traceback을 출력하지 않는다.

기존 summary의 OD 쌍 수 185,292, 상위 OD CSV 합계 8,668명, 오전 883,427명을 대조한다. 현재 오전 파일의 인원도 비교하고 불일치가 있으면 버전·갱신 확인 필요 상태로 남긴다. OD 쌍은 노선을 합친 정류장 쌍이며 여정 수가 아니다.

합성 테스트는 역순 공유·순번 공백·충돌·중복·반복 방문·그룹 간 잘못된 연결 방지·후보 쌍 수·유효기간 경계 가정·행정구역·전체 보고서 경로를 검사한다. 실제 원시 이용 기록을 fixture로 사용하지 않는다.

다음 추출은 추천 노선 ID와 공유 구간 정류장 ID를 시작점으로 하되 전체 원천 방문열·순번·반복·버전 후보를 보존한다. 방향/버전 키, 유효기간 경계, 중복 원인, 반복 방문 식별, 주행시간 출처, 회전·회차·복귀, 정상 시간표는 관련 담당자 합의·추가 자료가 필요하다.
